# F127.5 Minions on the address

> **Plan**, F127's fifth child, from the F127.3 to F127.5 plan page Louis approved (2026-11-11): "`StartMinion(address,
> …)`: `puls.find-recipe`, checked against Puls's `Calls`, its model and tool as its role says". Written and built
> unattended (Louis, 2026-11-12: "finish F127 unattended"), each finding the recommended of three under *Claude's
> picks*. This file changes only under *Approved during the build*.

## Context

**What Louis asked:** one address for every call an identity makes (ADR 0117): to another identity, to a role, and to
its own minion. F127.3 put the first three on `AskAgent`; `StartMinion` still takes a role file's name
(`puls-minion-find-recipe`), and no list in code says which minions an identity may start.

**What exists:** `StartMinion(role, tool, task, stronger)` checks the role's name, that the tool is one the caller
holds, the model for the role (`MINION_LLMS`, ADR 0081: a minion runs a local model), the limits, then opens the
minion at depth 2 on this instance; the web's card reads the call's `role`. The resolver knows minion files, and
`AskAgent` would resolve one if its file's name were written (`puls.minion-find-recipe`). Puls is paused and no voice
starts a minion today (ADR 0081 took them off the cook), so nothing paid runs here.

## Design

### What changes, in plain words

- **A minion has an address:** `puls.find-recipe`, the identity and the minion's function; `StartMinion` says it is a
  minion, so the address finds the file `puls-minion-find-recipe` and no other.
- **Its identity's `Calls` list it**, as for an agent; an address not listed is refused naming the ones that are.
  A minion runs on this instance, so an address with a server is refused.
- **`AskAgent` never opens a minion**, and its list of an identity's roles names only specialists.
- **A mode's prompt lists only the agents** among its `Calls` under *Agents you may ask*; the minions stay in the
  roles that hand work to them.
- **The web's card** reads the call's `address`.

## Steps

Each step test first, one commit, `core.tests` when a folder or a name is added.

1. **The plan**, its pictures drawn.
2. **A minion's address:** `ResolveMinion` finds `{identity}-minion-{role}` at the minion level; `Resolve` (for
   `AskAgent`) no longer finds a minion, and the roles it names are specialists. Tests: `AgentAddressesTests`.
3. **`StartMinion` takes the address:** read, refused with a server, checked against the caller's identity's
   `Calls`, resolved as a minion; then the tool, model and limit checks as before; the minions guide and the web's
   card read the address. Tests: `MinionToolsTests`, `DelegationTests`; goldens.
4. **Puls lists its minions:** `PulsCall` gains `puls.find-recipe` and `puls.web-price-lookup`; a mode's prompt lists
   only the agents among its `Calls`. Tests: the prompt's list, Puls's catalogue; goldens.
5. **The docs:** ADR 0117's record, core's and Puls's design docs, the minions guide's mentions, the work log, the
   write-up, the full suite, this plan deleted.

## Verification

- **Each step:** the tests of what it touches; `core.tests` for new folders and names.
- **No live run:** a minion runs a local model and Puls is paused; the tests carry the check (Q5).
- **Full suite** once, in step 5.
