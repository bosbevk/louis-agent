# F160.1 The framework's pages, written new on its own site

A plan, F160's first child: the framework's old pages are thrown away from louis-agent.dev, and its own site,
`louis-agent.site-framework` with its host, is built with seven pages written new that walk a developer from what
the framework is to building on it, name the features shipped this month, and link down into the docs by path. It
runs on :5084; F160.2 gives it its agent and F160.3 puts it on `framework.louis-agent.dev`.

## Context

**What Louis asked**, and his eleven picks, are in [F160's plan](F160-the-framework-site.md#context). This child
holds the ones about the pages: throw away what is there ("totally forget what was we will build it new and delete
the old"), seven pages in a visitor's order, doc links by path, every picture from our tool ("we redraw pics from our
tool"), the site of its own ("framework will also become a subdomain").

**What was looked up.** How others lay out a framework's pages and serve them to agents:
[Microsoft Agent Framework](https://learn.microsoft.com/en-us/agent-framework/) (Overview, Get started in seven
steps, Concepts, Capabilities, Integrations, Support), [Anthropic](https://platform.claude.com/docs/en/home) (a
journey of get started, build, evaluate, operate), [Diátaxis](https://diataxis.fr/) (the four kinds of doc, which
ADR 0013 follows), [Starlight](https://starlight.astro.build/guides/sidebar/) (a sidebar from folders and headers),
[llmstxt.org](https://llmstxt.org/) and its uptake (97% of the files get no requests), the
[MCP resources spec](https://modelcontextprotocol.io/specification/2025-11-25/server/resources) (own schemes allowed),
Microsoft Learn's and Mintlify's docs servers (search and fetch tools), and
[Google's URL guidance](https://developers.google.com/search/docs/crawling-indexing/url-structure) (descriptive
words, hyphens, a simple structure).

**What is there.** Ten framework pages on louis-agent.dev, hidden from the menu since FX176. They follow the
repository's layout, seven hold raw HTML (which ADR 0125 no longer allows), one says "The repository is private",
untrue since 2026-11-13, and none names pacing (F155, F156), Reset my session (F153), the answer's motion (F154),
the two themes (F151) or the naming rule (ADR 0126). A new site starts from the starter
([Spawn a site](../guides/spawn-a-site.md)): a site project and a small host program that serves it, as
`louis-agent.site` has `louis-agent.site-api`. `SiteMapTests` holds that every shipping project is named on some page
of the site; the project names live today only in the parts step 1 deletes.

## Design

### The shape, in plain words

**We throw away what is there, and start new.** Nothing of today's framework pages is moved, reworked or copied:
not a page, a part, a picture, a test, a sentence or an address, and no old address is sent on. Step 1 deletes them
all from louis-agent.dev; each new page is written from the code as it stands, its tests first. What goes:

| What | Where |
|---|---|
| The ten pages | `Pages/HowItWorksPage`, `ProofPage`, `BuiltOnItPage`, `WhatsComingPage`, `Pages/Framework/ArchitecturePage`, `IdentitiesPage`, `PacksPage`, `BuildYourOwnPage`, `CsharpAgentFrameworkPage` |
| Their redirects | The eight moves in `MovedPages` that lead to them (`/how-it-works`, `/architecture`, `/identities`, `/packs`, `/build-your-own`, `/proof`, `/built-on-it`, `/whats-coming`), with their tests; the moves to the guesthouse and the contact page stay |
| Their parts | `Components/Architecture/` (the seven families, `WhereItRuns`, `DemosFamily`), `PrinciplesView` |
| Their pictures | `Graphs/Framework/` (six graphs), `Graphs/ProofGraph`, `Graphs/DemosGraph` |
| Their tests | Each test of those pages, parts and pictures, and each claim in `Claims/` that names one |
| Their menu | The framework group in `SiteLayout.razor`, and the guide's framework focus under those addresses |

The theme's component guide (`/framework/theme`) stays on louis-agent.dev: it was built with the themes (F151), and
the landing page and the theme guide link to it.

**A site of its own.** `src/site/louis-agent.site-framework`, spawned from the starter and stripped to what it
needs (no chat page, accounts or eval studio), names its areas in one place and wears glass and flat, light and dark.
`src/site/louis-agent.site-framework-api` serves and prerenders it, as `louis-agent.site-api` does, and runs on
:5084 beside the selling site in `src/site/docker/docker-compose.yml`. It runs no agent yet (F160.2).

**Seven pages, in a developer's order**, at the root of the site's address, a page's name following its address,
each section its own address under its page (ADR 0107):

| Page | Address | What it tells |
|---|---|---|
| Overview | `/` | What it is, the engine, an identity and a pack, why C#, your own hardware, and a picture naming every project that ships |
| Getting started | `/getting-started` | Your program in a few lines, what it loads, whose is what, where it stands |
| How it works | `/how-it-works` | One turn through every layer, the web with the backend, identities, packs, the rules every turn keeps |
| Features | `/features` | What it does, by area: the engine (pacing), the API (sessions, `Stream-Paced`), the web (the answer's motion, Reset my session, the guide's caption, two themes with light and dark), the code (ADR 0126's naming rule) |
| Cost and evals | `/cost-and-evals` | The ledger, how the rand come about; the evals' sections each marked coming soon, while they are reworked |
| Examples | `/examples` | Puls, the coding agent, the guide, and what's coming |
| Comparison | `/comparison` | louis-agent beside Microsoft Agent Framework and Semantic Kernel |

**Every picture is drawn by our tool.** A page's picture is a spec for `louis-agent.diagrams`, shown with
`GraphView`, drawn new for its page; none is an image file or drawn by hand.

**Every section hands off to the docs by path.** A section ends with its doc links: `DocLink` given a repo path such
as `src/docs/adr/0126-a-name-says-what-it-is-by-its-kind.md`. Where a path leads is the site's one setting,
`.Docs(DocsAddress.GitHub(...))` on its areas, the docs site once it is up. A test fails on a path that isn't a file.

**Only configured components** (ADR 0125). The pages hold no HTML: bands, tiles, term lists and graphs from
`louis-agent.web`, and two parts it gains for what nothing draws yet: `CodeListing` (code with its language) and
`ComparisonTable` (rows against columns). A page over about a hundred lines splits into parts (ADR 0034).

## Steps

Each is one commit, its test written first and seen failing; each visible step is rebuilt on :5084 for Louis.

1. **Throw away what is there.** Everything in the table under *We throw away what is there* is deleted from
   louis-agent.dev. No test first: it removes, and the site's tests show nothing else leaned on what went.
   `SiteMapTests` can't hold meanwhile (the project names lived in the deleted parts), so it is set aside with its
   reason, `[Ignore("F160.1: the framework site's Overview names every project again, step 5")]`.
2. **The framework site and its host.** Spawned from the starter, stripped to its pages, glass and flat; its host
   serves and prerenders it on :5084 in the site's compose file; both in the solution and `SolutionLayoutTests`.
   *Test:* the host answers `/` with the site's title, prerendered. If serving a site needs the API's services, the
   host starts the API with no identity, and the step says so.
3. **The doc link.** `louis-agent.web.docs`; the framework site names GitHub. *Test:* a path leads to
   `github.com/bosbevk/louis-agent/blob/main/{path}`; a site that names no docs' address fails at start with its
   reason; `DocPathsTests` fails on a path that isn't a file.
4. **`CodeListing` and `ComparisonTable`.** *Test:* code is drawn as text, never markup, with its language named;
   a row's cells line up with the columns, and a row with too few is refused.
5. **Overview**, `/`, with a picture of the whole framework naming every project that ships. *Test:* it answers
   with its title and description; no framework page holds an HTML tag (a test over every page from here on);
   `SiteMapTests`, moved to this site's tests, is back on and passes.
6. **Getting started.** *Test:* its program is the coding agent's real `Program.cs`
   (`demos/louis-agent/hosts/louis-agent.coding-cli/`), read from the file, so it can't drift.
7. **How it works.** *Test:* every pack in `packs/tools/` and every identity is named, read from the disk.
8. **Features.** *Test:* each feature names a doc that exists and a setting or type that exists (`STREAM_PACE`,
   `Stream-Paced`, `SessionReset`, `LookSwitch`), so a removed feature fails the page.
9. **Cost and evals, Examples and Comparison**, what's coming as Examples' last section; the site's menu, sitemap
   and crawler pages. *Test:* each number names the ledger, price table or eval it comes from; each claim of
   Comparison names the file that proves it; every page is in the menu and the sitemap.
10. **The docs, the write-up, the plan folded.** The design docs of the framework site and `louis-agent.web.docs`,
    the selling site's doc without its framework pages, the write-up, records.

## Verification

The touched tests per step; before the pull request, `main` merged and the full unit suite. By eye on :5084 at 1280
and 390 px wide, both themes, light and dark, each page held to louis-agent.dev's landing page, the site's best;
louis-agent.dev on :5080 checked for a link that leads nowhere. No paid run: no agent runs on this site yet.

## Concepts, and where they sit in GOAL.md

- **One source of truth with several doors** (steps 3, 8): a page links to the doc by its path instead of repeating
  it, the pattern the docs site, `/v1/docs` and `docs://` will share. *Skill 11, protocols.*
- **Information architecture by the reader's need** (steps 5 to 9): Diátaxis's kinds, a journey from overview to
  reference. *Skill 20, extensibility*, since it is how someone finds their way into building on it.
- **Tests that hold a page to the code** (steps 6 to 9): a claim names a file, a type or a setting, and fails when
  that goes. *Skill 18, testing and shipping.*

## Approved during the build

- **The framework's pages are a package a site turns on, like the accounts** (Louis, 2026-11-17: "the framework must
  be a package like accounts", his pick A of three): `src/web/louis-agent.web.framework` holds the pages, their parts,
  their pictures and the layout they wear, and `.Framework()` on a site's areas brings them to its router;
  `louis-agent.site-framework` is the thin app that names it, with its host, styles and page shell. The pages' rows of
  the namespace map read `LouisAgent.Web.Framework.Pages` (and `.Components`, `.Graphs`) in
  `src/web/louis-agent.web.framework/`, their tests `src/tests/web/louis-agent.web.framework.tests`.
- **The host draws the pages a site's areas bring, but none behind a sign-in** (Louis, 2026-11-17: picks A and A
  of three; "/Login / register / password-reset etc is public", "not the pages after the sign in"). The web tells
  the host the areas' page assemblies through a contract both already reference (`SitePageAssemblies` in
  `louis-agent.api.contracts`), so turning a package on is enough on every site; a page behind a sign-in says so
  with Blazor's own `[Authorize]` (the accounts' profile), and the host never draws it for a search engine.
- **A new layout made for this kind of content** (Louis, 2026-11-17: "we must design a new layout which fits this
  type of content", then "do research on the layout first and give me 3 designs"): researched against Microsoft
  Learn, Tailwind, Supabase, Starlight, the AI SDK, Linear and Stripe, three designs built as real pages, and his
  pick "A, with B's hero on the Overview": the docs layout in three columns (a header with search, light and dark
  and "Ask louis-agent · AI"; the seven pages grouped on the left with the current page's sections open; a readable
  middle column; "On this page" and "Ask about this page" on the right; each section ending with its doc chips;
  previous and next at a page's foot), and the Overview opening with a hero band, its headline beside the code and
  two buttons. It lives in the framework's pages' package.
- **Eleven steps, not ten** (Louis, 2026-11-17: "commit and go step 4", to the order put to him): the layout is
  step 4 (the framework's frame: three columns, the grouped menu, on this page, ask about this page, previous and
  next, and the Overview's hero); step 5 is `CodeListing`, `ComparisonTable` and the themed figure; steps 6 to 10
  are the pages in the plan's order (Overview, Getting started, How it works, Features, then Cost and evals, Examples
  and Comparison with the menu); step 11 is the docs, the write-up and the plan folded.
- **A picture follows flat or glass by a palette per theme in the diagram engine** (Louis, 2026-11-17: "if we need
  to add diagram types we add it in diagrams and C", his pick C of three): the engine keeps its own values for each
  theme, chosen by the page's `data-theme` as it already chooses light and dark by `data-style` (`PageScheme`), so a
  picture inline on a page wears flat or glass, light or dark, and a picture as a file is unchanged. A kind of
  picture the pages need that the engine lacks is added to `louis-agent.diagrams`, never drawn another way. The
  page's figure is `DiagramFigure` in `louis-agent.web`, drawing `DiagramRenderers.RenderForPage` inline. Step 5.
- **Every picture carries the louis-agent brand, in its footer** (Louis, 2026-11-17: "every image must have our
  branding", his pick A, the engine draws it into every picture, files and page copies alike; then "Distinguise
  between header and footer on image", his pick "brand in the footer"): a picture's header holds its title and its
  kind under a hairline; its footer, over a hairline, holds how to read it, the louis-agent mark and wordmark at its
  right, and the caption under. Drawn by the engine in the picture's own colours, so it follows the page's theme; the
  docs' pictures are drawn again once by the diagram tool.
- **The brand is the site's own wordmark, and every picture is written in the site's fonts** (Louis, 2026-11-17:
  "must look like this one just a bit smaller", "all diagrams must use font from website", "it is like the
  framework defaults", "must also move in a bit"): the footer's brand is "l", the violet mark as its "o", then
  "uis-agent"; a picture's words read the site's `--bs-font-sans-serif` and `--bs-font-monospace` on a page and fall
  back to the framework's defaults, Geist and Geist Mono, as a file; the header's words and the brand stand in from
  the picture's sides. A card may wear a tone, and each family's cards wear its colour. Step 8.
- **A box may hold its boxes in columns, and the framework's families each wear one colour** (Louis, 2026-11-17:
  "split this in two columns", "give each one a color this color we can then reuse talking about it", "take these
  tags out", "remove the unneccesary sapce"): `NestedBox.Columns` in the engine, one column by default; the families'
  colours in `FrameworkFamily`, asked by every picture and page that talks of a family; and the page's middle column
  fills its width, as much room on its right as on its left, a picture as wide as the column.
- **Thirteen steps, not eleven** (Louis, 2026-11-17: "continue with 13 steps"): step 6 is the Overview, with each
  of the five families under its own heading and an overview picture; step 7 the places area below; step 8 the
  picture's header and footer, with the brand, in the engine; steps 9 to 12 the other pages; step 13 the docs, the
  write-up and the plan folded.
- **Every place's address is an area a site names, `.Places(home, site)`** (Louis, 2026-11-17: "A .Places() area",
  his pick A of three): the router's catch-all and the layout it draws a place in move from `louis-agent.web` to a
  package of their own, `src/web/louis-agent.web.places` (`LouisAgent.Web.Places`, tests in
  `src/tests/web/louis-agent.web.places.tests`), so a site that wants its places doesn't take the admin's pages
  with them; the area reads the addresses from the site's pages and its areas', and both sites name it instead of
  registering their addresses by hand in the program and the host. A page behind a sign-in or the admin's key has
  no places, by the host's own rule, so a place's address can't draw it around the router's check. Step 7.
- **Features lists everything the framework does** (Louis, 2026-11-17: "is that the only features we have?", then his
  pick A of three, "research all our features and list them this is why people would want it"): 39 features in
  seven areas (the engine, the models, where it runs, the web, its guards, what it measures, the code), each written
  from the summary of the code that does it, each naming that code and a doc, both held to the repo by the page's
  test; the page opens on its areas at a glance, a card an area in its own colour (his pick A of three). Step 11.
- **The evals keep their sections, each marked coming soon** (Louis, 2026-11-17: "keep the evals sections, but on
  their pages must be coming soon. It needs to be reworked"): Cost and evals keeps its places for the evals, in the
  contents and "On this page", but each says the evals are being reworked and are coming, and makes no claim about
  how they work today; the cost's sections are written in full. Step 10's test holds that no eval section claims
  more than that.
- **The framework's site opens flat, light, and stays flat** (Louis, 2026-11-17: "this ones default will be the flat
  white theme so we can add some nice things along to way to make it more functioning, but we keep things flat"):
  flat is its first theme and its page's first paint, glass offered beside it; what the site gains along the way
  keeps to flat's look. Then (Louis, 2026-11-17: "we can hide this only light or dark switch, this must always load
  flat so no glass theme here yet"): the site offers flat alone, so its switch shows only Dark and Light, and the
  framework's switch puts a theme a browser remembers but the site doesn't offer back to the site's first. Step 11.

- **A page's picture is drawn by the diagram engine's own renderer, as SVG on the page** (Louis, 2026-11-17: "we
  must use digrams to render the graphs in svg on the page"). Not `GraphView`, which lays a flow out with the
  engine but writes its own markup: a page's picture is a `DiagramSource`, any of the engine's kinds, drawn by
  `DiagramRenderers.RenderForPage`, the same SVG the docs' pictures are, as the chat's `DrawnCard` already does for a
  ticket. The page's figure that holds it is a new part of `louis-agent.web`, put to Louis with three options in
  step 4, beside `CodeListing` and `ComparisonTable`.
- **A page's picture follows the visitor's look** (Louis, 2026-11-17: "so we need light/themed diagrams"): glass or
  flat, light or dark, as the page around it. The engine already draws a picture inline with its styles kept to it
  (`PageSvg`, `@scope`) and lets the page's variables reach it, which is how the chat's ticket follows the theme
  (`--ticket-*`); the docs' kinds (flow, sequence, classes and the rest) still hold their dark colours in the
  drawing. How they come to read the theme's names, and whether that is this child's or a feature of its own, goes
  to Louis with the figure's options in step 4.
