# F151.8 Recorded again, and closed

A plan: how the showroom's three conversations are recorded again and its films exported again in the new look,
how the live site is checked, and how F151 is closed. It is the last child of
[F151 Two themes, each light and dark](F151-themes-and-styles.md), after
[F151.7](F151.7-the-pictures-follow.md). It has eight steps, each with its own picture.

## Context

When the design was chosen Louis said "the plan must include that the demos sites get new recordings for this".
A demo page plays a recording of a real conversation with that business's agent, and the page's questions and its
website's places must be the ones the recording was sent, which tests hold. The films on the site are exported
from its pages, and the export keeps a hash of each film's own files, so a film whose styles changed is out of
date.

How a recording is made was read in `src/site/recordings/record-showroom.sh`. It runs the site's own image on
this PC, on a spare port open to this PC only, and asks each business's agent the page's questions word for
word. Run plainly it is a dry run: no mail goes out and what it heard is kept in a scratch folder and thrown
away. Run with `SEND_MAIL=1` it is the recording: each booking sends one mail to Louis, and the three files under
`wwwroot/recordings/showroom/` are replaced. `ONLY=` names one business. The script's own note says a run costs a
few cents a business.

Two of Louis's standing rules meet here. No mail is sent without his word, and a run that spends money waits for
his go. So the dry run may be made and its cost reported, and the recording itself is his to start or to say go
to.

## Steps

Each step is one commit where it changes a file. Stop after each for Louis's review.

### Step 1: the plan is kept

![This plan and its pictures](diagrams/F151.8-recorded-again-and-closed-step-1-the-plan-is-kept.svg)

A docs-only step. This plan and its pictures are committed, and its row in the plans' index says it is approved.

### Step 2: a dry run

![The three conversations are run with no mail and nothing kept](diagrams/F151.8-recorded-again-and-closed-step-2-a-dry-run.svg)

The site's image is built from this branch, and the script is run plainly, one business at a time. No mail goes
out and nothing is saved. `ShowroomPagesTests` holds that each page's questions are the script's, so run it
first. What to look for in what comes back: each agent still opens the place the page shows, still draws its
card, and still asks before it sends. Report what each agent answered and what the run cost. It has no commit.

### Step 3: the recording, on Louis's go

![The real recording: each booking mails Louis once, and the three files are replaced](diagrams/F151.8-recorded-again-and-closed-step-3-the-recording.svg)

**This step waits for Louis.** The recording sends him one mail for each booking and spends money, so it is run
only on his word, or by him. Tell him what the dry run showed and what the real one will cost, and wait.

Then `SEND_MAIL=1`, one business at a time, and the three files are replaced. `ShowroomPagesTests`,
`BusinessDemoTests` and the test that a recording's page lists its website's places must pass over the new
files. Each demo is then played on this PC from start to end, in glass and in flat, since a recording drives
what the page shows: the place it opens, the card it draws, the words beside it.

### Step 4: the films

![A film whose styles changed has a new hash, so it is exported again](diagrams/F151.8-recorded-again-and-closed-step-4-the-films.svg)

The film export's tests say which films are out of date, by their hashes. Each is exported again from the page
as it now looks, with the tool's own encoder. A film is a picture of a screen, so it is exported in the dark
style, which is what it is shown in on a page of either style. If the export needs the encoder's image built, or
takes more than a few minutes a film, say so before starting.

### Step 5: the live site

![After the deploy every route is opened on the live site in all four looks](diagrams/F151.8-recorded-again-and-closed-step-5-the-live-site.svg)

The recordings and films reach the live site with this child's own pull request, so this step is done after
step 8's merge and its deploy, and is written here because it is the feature's last check. Every one of the 22
routes is opened on louis-agent.dev with `/check-a-page`, in all four looks, at 1920 by 1080 and at a phone's
width. The three demos are played. One real question is asked of the guide, and its cost reported. Anything
wrong is a fix of its own, with its own id.

### Step 6: the docs of every project

![Each project the eight children changed has its design doc and pictures read against the code](diagrams/F151.8-recorded-again-and-closed-step-6-the-docs-of-every-project.svg)

List the projects F151 changed, from the eight children's commits, by folder. For each, read its design doc and
its how-to against the code as it now is: its parts, its structure table, its settings, how to extend it. A
picture that no longer shows the code is changed in its JSON and redrawn by the tool. Then the lists no single
feature owns: the readme's *Where it stands*, the roadmap's *What exists*, the indexes, and the repo map, which
gains the two theme packages.

### Step 7: the records, and the plans go

![The work log gains its rows, the TODO loses F151, and the nine plans and the mockups are deleted](diagrams/F151.8-recorded-again-and-closed-step-7-the-records-and-the-plans.svg)

The work log gains a row for F151 and one for each child, and its counts follow. The TODO's F151 row is deleted.
The goal's map moves what F151 delivered into *Have today* under extensibility. The write-up for extensibility
has F151's section, with what was built, what was measured, the trade-offs and what did not work, and its row in
the write-ups' list. Then the nine plans, their pictures and the mockups folder are deleted, and their rows leave
the plans' index. `WorkLogTests` and `WriteUpsTests` hold the records.

### Step 8: the pull request

![Main is merged in, the full unit suite passes, and the last pull request closes F151](diagrams/F151.8-recorded-again-and-closed-step-8-the-pull-request.svg)

`main` is merged in, the solution builds, the full unit suite passes, and the pull request is opened on Louis's
word. After he merges it and the deploy lands, step 5 is done on the live site.

## Verification

The tests named in each step, then the full unit suite. The dry run and the recording are live runs: the dry run
may be made and its cost reported, and the recording waits for Louis. The live site is checked by eye in step 5.

## Concepts

This child is the end of a feature done properly: the content a visitor watches made again from a real run, the
docs of every touched project read against the code, and the plans removed once what lasts has a home. That is
testing and shipping, skill 18 in [the goal](../GOAL.md). The dry run before a paid, mail-sending run is human in
the loop, skill 16.
