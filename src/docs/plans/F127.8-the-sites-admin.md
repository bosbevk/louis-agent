# F127.8 louis-agent.dev's admin: an overview first

> **Plan**, F127's last child, after F127.7. Louis, 2026-11-12: "let's finish 127 first". The admin is behind the admin
> key for now, and accounts with a role come later (F108). Of three UI designs he picked **A. Overview first**. This
> file changes only under *Approved during the build*.

## Context

louis-agent.dev has a guide in its corner on every page, but its owner can't see what the guide does: how many people
talk to it, what that costs, which parts of the site they talk on, which demo businesses they try, or whether a lead
came of it.

What already exists:
- **The framework's admin frame.** `AdminShell` draws it, and `AdminGate` asks for the key and keeps it in the
  browser. The API's admin group sits behind `ADMIN_KEY`.
- **The areas builder's `.Admin(layout, views)`**, which code-review, Puls and the starter use. louis-agent.dev names
  none yet.
- **The usage ledger**, `usage-{yyyy-MM}.jsonl`, with each request's session, turn and cost. It has no page, no part
  of the site, no identity and no lead.
- **Conversations** live in the API's memory only, and leads are only mailed.

## Design

### What changes, in plain words

- **A turn log.** At the end of every turn the API writes one line beside the ledger,
  `turns-{yyyy-MM}.jsonl`: when, the session, the turn, which identity answered, the page, the part of the site, and
  the names of the tools the turn called. It keeps no visitor words, so there is nothing private in it.
- **An overview endpoint.** `GET /v1/admin/overview?day=…`, behind the admin key, joins the turn log and the ledger by
  session. It returns today and this month (talks, cost in the display currency, and the talks that used each tool),
  the talks by part and by identity, and the latest twenty talks.
- **The site names what it counts.** The API counts every tool and names none. The site's admin area says which to
  show and what to call it: `counts => counts.Tool("SendLead", "leads")`.
- **The overview page** in the framework's admin is design A:
  - three figure cards;
  - one-colour bars by part and by identity;
  - the latest talks as a table.
- **louis-agent.dev names its admin** with a small layout of its own. It is linked from nowhere public.

## Steps

Each step is test first and one commit, and stops for Louis's review.

1. **The plan**, its four pictures drawn.
2. **The turn log**: `TurnLogRecord` and `TurnLog`, written by `TurnStream` when a turn ends, with the page and focus
   from the message's request. Tests: a turn with a page, a focus and a tool call writes one line with them; nothing
   is written without a folder.
3. **The overview reply**: the records, `OverviewReader` joining the turn log and the ledger, and `OverviewHandlers`.
   Tests: today and the month, the cost in rand, the parts, the identities, the tools, the latest list, and an
   unknown cost staying `null` (ADR 0007).
4. **The counts a site names**: `counts` on `.Admin(…)`. Test: `SendLead` named as leads is what the page shows.
5. **The page**: `Overview` and its components, with a menu link first in the admin. Tests: bUnit against a stub
   reply, and its golden.
6. **louis-agent.dev's admin**: its `AdminLayout`, `.Admin(…)` with `SendLead` as leads, and `ADMIN_KEY` in
   `.env.example`. Tests: `SitesNameTheirAreasTests`, and the admin's routes.
7. **Checked live, documented, F127 closed**:
   - the site on 5083 with a test key, a few guide talks on the test credit, and the overview at desktop and 390 px;
   - the docs, F127's work-log row and TODO, and F127's write-up;
   - the plan deleted;
   - the full suite, and one PR.

## Verification

- Each step runs the tests of what it touches, plus `core.tests` for new folders and names.
- Live: run guide talks on `/pricing`, `/demos` and `/framework`, then open `/admin/overview`. The talks, the rand,
  the parts and a test lead must match what was done. Without the key, `AdminGate` asks for it. The talks cost a few
  cents of test credit, reported after.
