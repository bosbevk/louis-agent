# F97.3 Tool search for the built-in tools

> **Plan.** How the coding agent stops sending all ninety-eight of its tools to the model on every request, and finds
> the one it needs with a search of its own, on Anthropic, measured before and after. **Elsewhere:** the parent,
> [F97](F97-a-skill-usable-in-its-chat.md).

![F97.3 at a glance: a FindTool of ours, the tools each toolset keeps loaded, the rest deferred on Anthropic, a TOOL_SEARCH setting, and a coding eval that measures it](diagrams/F97.3-tool-search-overview.svg)

## Context

F97 was re-aimed on 2026-11-26, in Louis's pick: with no skill called by its own name any more, F97.3 brings tool
search to the agent's built-in tools, "since the research says selection improves when tools load on demand", with a
paid proof on Haiku 5.5 first. On 2026-11-27 he asked for the research to be done properly before any choice, and
then picked three things, each over two others: our own search tool, each toolset saying which of its tools stay
loaded, and a `TOOL_SEARCH` setting that is `auto` by default.

What it is for. A coding chat with every toolset sends 98 tools, about 17,000 tokens of definitions, on every request
(counted from the coding catalogue's `ModelRequestSnapshot.json`), beside an 11,500-token system prompt. Anthropic
writes that a model's "ability to pick the right tool degrades once you exceed 30–50 available tools", and suggests
tool search from ten tools or ten thousand tokens of definitions
([tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)).

What was looked up, on 2026-11-27. Anthropic's tool search is stable, needs no beta header in its docs, and lists
Haiku 5.5. A tool marked `defer_loading` is still sent in full on every request, but it stays out of the model's
context and out of the cached prefix until a search finds it; at least one tool must stay loaded, and a deferred tool
can't carry `cache_control` (a 400). Besides Anthropic's own server-side search, the docs describe a custom one: our
tool answers with a `tool_result` holding `tool_reference` blocks, and the API expands each into the tool's
definition ([custom tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)).
Anthropic measured, on internal MCP evals, Opus 4 going from 49% to 74% and Opus 4.5 from 79.5% to 88.1%, with about
85% fewer tokens ([advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)); nothing is published
for Haiku. Others built it the same two ways. OpenAI's Responses API has a hosted and a client-run search
([OpenAI](https://developers.openai.com/api/docs/guides/tools-tool-search)); Spring AI's advisor searches in the app
and reports 64% fewer tokens on Claude with 28 tools
([Spring AI](https://docs.spring.io/spring-ai/reference/api/tools/tool-search-tool.html)); LangGraph BigTool gives the
agent a retrieval tool ([BigTool](https://github.com/langchain-ai/langgraph-bigtool)); Claude Code keeps its own tools
loaded, defers MCP tools, and turns search on by itself past a share of the context
([Claude Code](https://code.claude.com/docs/en/mcp)). All three warn that a search always returns its closest
matches, even poor ones, and that names and descriptions are what it finds.

What our SDK carries. In Anthropic's C# SDK at 12.53.0 the `IChatClient` adapter reads `DeferLoading` from a tool's
`AdditionalProperties`, and a tool result's `Block` union holds a `ToolReferenceBlockParam`, passed through when an
`AIContent` carries it as its raw form ([the adapter at the tag](https://raw.githubusercontent.com/anthropics/anthropic-sdk-csharp/Anthropic-v12.53.0/src/Anthropic/AnthropicClientExtensions.cs)).
Anthropic's server-side search can't be used yet: the adapter drops `server_tool_use` and `tool_search_tool_result`
from the next request, which [PR #242](https://github.com/anthropics/anthropic-sdk-csharp/pull/242) would fix and
hasn't.

What no source confirms, so step 1 proves it: whether a chat with thinking on stays valid when a deferred tool is
found and called, and whether our automatic cache marker sits well beside deferred tools. The plan stops at step 1 if
either fails.

## Design

### 1. What a person gets

Nothing changes in what they type. The coding agent's first request now carries the handful of tools each toolset
keeps loaded plus `FindTool`, and every other tool deferred. When the model needs one it can't see, it calls
`FindTool("stage the changed files")`, the API loads the best matches, and the model calls the one it wants, by its
own name, in the same answer. A small chat, such as the guide's with a few tools, has nothing deferred and no
`FindTool`, because `auto` turns search on only past ten tools that could be deferred.

### 2. FindTool, in core

`FindTool` is the engine's own tool, beside `UseSkill`, because it needs the chat's tool list. It scores each tool of
the chat's frozen list (FX4) by the query's words found in its name, its description and its parameters' names and
descriptions, the fields Anthropic's own search reads, and answers with the names of the best five, as a
`FoundTools` record. It names no provider: what the model is handed is the strategy's job (section 3). A plain word
score needs no package (ADR 0055); a search that finds nothing says so, and lists the toolsets' names.

`FindTool` reads only the tool list, so its answer is the same on a replay; it is recorded like any tool, as JSON
(FX235), and the replay plays the same record back.

### 3. The strategy, per provider

Where providers differ, one interface with an implementation per provider (ADR 0003). `ILlmProvider` gains
`CreateToolSearch(LlmOptions)`, whose default, `NoToolSearch`, says search isn't available, so OpenAI and Ollama send
the full list as today and their chats never get `FindTool`. `AnthropicToolSearch` does two things on each request,
below the replay so the history and the replay's keys stay provider-neutral (ADR 0008): it marks every deferred tool
with `DeferLoading`, and it turns each `FindTool` result's names into `tool_reference` blocks. It never puts the
cache marker on a deferred tool.

### 4. Which tools stay loaded

Each toolset's built-in skill names its few most-used tools in its front matter, as `metadata.loaded`, read by the
strict header reader (ADR 0063). The engine's own tools (`FindTool`, `UseSkill`, `GetToday`) always stay loaded.
Every other tool of a chat is deferred when search is on. `ToolsetCatalogTests` holds that every name a toolset keeps
loaded is one of its tools.

### 5. When search is on

`TOOL_SEARCH` is `auto`, `on` or `off`, a `ToolSearchMode` enum parsed once with `SettingChoice` (ADR 0024). `auto`
turns it on when the provider has a search and a chat has more than ten tools that could be deferred; `on` forces it,
for a test; `off` is the "before" of the measure. It goes in each host's settings and in SETUP.

### 6. Measured on a coding eval

The coding agent has no eval yet. `coding.eval.json`, beside its voice, asks for jobs that each need one tool, such as
"what changed in the last commit?" (`ShowCommit`) or "add Newtonsoft.Json to the project" (`DotNetAddPackage`), with a
`used` fact for the tool and a judge's criterion for the answer. It runs live with `TOOL_SEARCH=off` before any of
the search exists, and again with it on at the end; the write-up compares the two (tools found, facts met, tokens,
cost), and its replay test runs free on every change, as the other three evals' do.

### What is reused

The tool list a chat froze at its start (FX4) is what `FindTool` searches and what is sent; nothing is added or taken
out mid-chat. The provider seam (`ILlmProvider`, ADR 0003), the raw-request hook the caching and thinking strategies
already chain (`RawRepresentationFactory`), the SDK's own `DeferLoading` and `ToolReferenceBlockParam`, the strict
header reader, `SettingChoice`, the engine's own tools beside `UseSkill`, the replay (FX235, FX258), and the eval
format and its replay tests (ADR 0134). No new package.

## Steps

Each step is one commit with its test, written first and seen failing, and a stop for Louis's review.

1. **The proof, paid, on Louis's word.** An integration test on Haiku 5.5 with thinking on and the cache marker:
   twenty tools, eighteen deferred, a custom search answering with `tool_reference` blocks through the SDK's adapter.
   It holds that the found tool is called, the next request is accepted with the thinking kept, and the cache is
   read on the second request. If it fails, the plan stops here and the result is recorded.
2. **The coding eval, and its "before".** `coding.eval.json` and its replay test; a live run with search off, on
   Louis's word, its first repeats kept.
3. **`TOOL_SEARCH`.** `ToolSearchMode` and its setting, parsed once, failing loud on a word it doesn't know.
4. **`metadata.loaded`.** The header reader learns the key, and a toolset carries the names it keeps loaded.
5. **`FindTool`.** The engine's own tool over the chat's frozen list, scored and capped at five, offered only when
   search is on.
6. **The seam.** `IToolSearch` and `NoToolSearch` on `ILlmProvider`; the engine works out the deferred names and the
   pipeline hands them to the strategy.
7. **`AnthropicToolSearch`.** `DeferLoading` on the deferred tools, `FindTool`'s names as `tool_reference` blocks, and
   no cache marker on a deferred tool.
8. **Each toolset's loaded tools.** Every pack's built-in skill names its most-used tools; the goldens are
   regenerated.
9. **The "after".** The coding eval live with search on, on Louis's word, its recordings kept, and the walk-through on
   `:5082`; the other three evals' replays still pass.
10. **The docs and the close.** Core's and the Anthropic library's design docs, SETUP, the extensibility write-up
    with the before and after, the work log and the TODO, and this plan folded and deleted.

## Verification

The unit tests of each step, the four eval replays, and the full suite before the pull request. By hand: a chat on
`:5082` with search on finds a tool it couldn't see, and the guide on `:5080`, with a few tools, has no `FindTool`.
Paid, each on Louis's word: the proof (cents), the coding eval before and after (one repeat each, about ten cents
each), and the walk-through.

**Done when** the proof is recorded; if it held, a coding chat on Haiku 5.5 with search on sends only its loaded tools
and `FindTool` undeferred, finds and calls a deferred tool in the same answer with no 400, the coding eval's before
and after are in the write-up, and every eval replay passes.
