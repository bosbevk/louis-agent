# F61.2 The pages, and the gate takes a signed-in person

> **Plan** (a child of [F61](F61-accounts-and-azure.md), which holds the design, the four diagrams and the namespace
> map). How the framework's web gets login, registration, confirmation, reset and profile pages on `louis-agent.accounts`,
> how the API's key gate accepts a signed-in person, and how Puls uses it all in its own words. Started 2026-11-07 on
> `feature/F61.2-account-pages`, under the parent's approval of 2026-11-07. Deleted when the work is done.

## Done when

On the PC, a person registers, confirms (the link from the log), signs in, opens a chat with no API key in the
settings, edits their profile and signs out, in Puls's words; `louis-agent.web` names no site.

## Steps

The parent's *F61.2* section, one commit each, test first:

1. The gate: `HostAuth.IsSignedIn`, `AgentKeyGate` passes the key or a signed-in person with `X-Requested-With`.
2. A session knows who opened it (`SessionOpener` from the cookie's claims; the tenant as a claim).
3. The browser's account client (`AccountApi`, the cookie auth state, `AccountState`; the header on every call).
4. The frame and the words (`SiteFrames.Account`, `AccountFrame`, `AccountText`).
5. Login and register.
6. Confirm, forgot, reset.
7. The profile.
8. The menu.
9. Puls uses it (its layout, its Afrikaans, its program; the starter the same).
10. Docs and write-up.

## Approved during the build

Picks taken unattended (Louis, 2026-11-07: "do all unattended"), each the recommended one of three:

- **The tenant travels as a claim** (step 2): the API reads who opened a session from the cookie's claims, and
  Identity's claims don't carry the tenant. Options: the API looks the user up (the API would reference the accounts
  library and SQL); the browser sends the tenant (a client could lie); **a claims factory in the accounts library
  adds a `tenant` claim, named once in `louis-agent.accounts.contracts`, which the API references** (picked: a claim
  is signed with the cookie, and the contracts project has no SQL).

## Verification

the Docker SQL Server. By hand, free: the Puls stack with `ACCOUNTS_SQL_URL` set, register, the link from the log,
sign in, chat with no key, the profile, sign out. No paid run.
