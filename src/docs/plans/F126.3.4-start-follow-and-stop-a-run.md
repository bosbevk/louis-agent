# F126.3.4 Start, follow and stop a run

A plan: how a person starts a run of an eval from the admin, follows it while it plays, and stops it. It is the
fourth and last child of F126.3, *runs and the run page*, in [F126 Evals, redesigned](F126-evals-redesigned.md), which
says what was decided and why. This file says what this child builds, then gives its nine steps.

![Five parts: the judge's cost on each turn, an estimate asked of the eval's row, a run that can be stopped, the card that starts a run after asking, and the run page that follows it](diagrams/F126.3.4-start-follow-and-stop-a-run-overview.svg)

## Context

**What Louis asked.** "F126.3.3 is done plan nxt fable medium" (2026-11-23). When he split the run pages the same
day he said what this child holds: the ask before a live run with its estimate, the page that follows a run as it
plays, Replay, Stop, and the judge's cost on the run. He also wants the framework done this week, so this plan
takes the least code at each choice.

**Why it matters.** Today a run is started with `curl`, and the admin's pages only read. A live run spends real
money, so the admin must say what it will cost before it starts and must be able to stop it. And half of a run's
cost, the judge's, is not on the run at all, so no page can say what a run really cost.

**What the code has, on `main` at `32c9ea15`.** The API starts a run at `POST /v1/admin/evals/{name}/runs`, answers
202 with the run's address, and plays it in the background, one run at a time. The run's file is written after
each conversation, and `GET /v1/admin/evals/runs/{id}` answers it as it goes and once it has ended. A second start
while one goes is refused with 409. Nothing can stop a run: the desk that plays it listens only to the host
shutting down.

A run ends as finished or as could not finish. A turn keeps the agent's cost and nothing of the judge's. Yet the
judge's calls are already priced: each one runs in a usage scope the judge opens, and when the host keeps a ledger
that scope holds the call's record with its cost, as the ledger stored it.

In the web, the evals' page draws a card an eval with one link, to its last run. The run's page reads once and on
Reload, and for a run that is going it says so and asks the person to reload. The web has no dialog control. The
one confirm it has, deleting an account, is an inline form.

The API runs an agent's turn under the request that asked it, so when the run drops its stream the turn in flight
is cancelled.

**What was read, on 2026-11-23.**

- Microsoft, [Asynchronous Request-Reply](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply):
  the start "returns an HTTP 202 (Accepted) status code", the client polls the address it was given, and "To
  provide a way for clients to cancel a long-running request, expose a DELETE operation on the status endpoint
  resource."
- Microsoft, [Cancellation in managed threads](https://learn.microsoft.com/en-us/dotnet/standard/threading/cancellation-in-managed-threads):
  "Cancellation is cooperative and is not forced on the listener", "The listener determines how to gracefully
  terminate in response to a cancellation request", and "A listener can listen to multiple tokens simultaneously by
  joining them into one linked token."
- Nielsen Norman Group, [Confirmation dialogs](https://www.nngroup.com/articles/confirmation-dialog/): "Use a
  confirmation dialog before committing to actions with serious consequences", "Be specific and inform users about
  the consequence of their action", and "Instead of Yes/No answers, provide response options that summarize what
  will happen for each possible response."
- Nielsen Norman Group, [Progress indicators](https://www.nngroup.com/articles/progress-indicators/): "Percent-done
  animation: Use for actions that take 10 seconds or more", and "give users the option to stop the process, in case
  they decide they cannot wait."
- Nielsen Norman Group, [Response time limits](https://www.nngroup.com/articles/response-times-3-important-limits/):
  "10 seconds is about the limit for keeping the user's attention focused on the dialogue."

**What could not be confirmed by reading.** How soon the spending really ends after a stop. The code cancels the
turn in flight, but what the model's provider bills for a call cut short is theirs to say. Step 8 stops a live run
and reads the ledger for what the cut-off turn cost.

## Design

### 1. In plain words

Every eval's card gets two buttons. **Replay free** plays the eval's last live run back from its recording and
starts at once, since it costs nothing. **Run live** opens an ask inside the card: how many conversations, one
repeat or three, and about what it will cost, worked out from what the last live run spent. The button that starts
it carries the cost in its own words.

Once a run has started, the browser goes to the run's page. While the run goes, the page reads it again every few
seconds and shows how many conversations are graded, the time and the costs so far, and one button, **Stop the
run**. Stop works at once: the conversation in play is dropped, and the run ends as stopped with every
conversation it had graded.

A run now shows two costs, the agent's and the judge's.

The four new states were drawn on the real pages of the running admin, with sample answers for the eval routes.
Each step that builds one names its picture. They are in [F126.3.4-screens/](F126.3.4-screens/), each at desktop
and phone width.

### 3. The judge's cost, on each turn

![The types: the judge hands back a mark with its cost, a turn keeps it, the rows carry the costs, the desk can stop a run, and the web's client starts and stops one](diagrams/F126.3.4-start-follow-and-stop-a-run-interface-design.svg)

The judge already opens a usage scope for each mark. After its call, that scope's total is the call's cost: the
ledger's own number when the host keeps a ledger, none when it keeps none, and a known 0 for an answer played back
in a replay. The judge hands that back with the mark.

```csharp
// Judge
public Task<JudgedMark> MarkAsync(string criterion, IReadOnlyList<TurnTranscript> conversation, ...);

public sealed record JudgedMark(Mark Mark, decimal? Cost);

// TurnRun gains, as an init property so a run's file made before it still reads
public decimal? JudgeCost { get; init; }
```

The player adds a turn's marks' costs the way costs are added everywhere, the known ones, and none when none is
known (`KnownCost.Sum`, ADR 0007). A repeat and a run add their turns' by a method, `SumJudgeCost()`, beside
`SumCost()`. The judge's cost is in the agent's currency, since one ledger prices both.

### 4. The estimate

A run in short, `RunRow`, gains what the run cost: the agent's, the judge's and the currency. An eval's row gains
its last live run that finished, the one a replay plays back. The row is then asked for the estimate.

```csharp
public sealed record EvalRow(string Name, string Agent, int Conversations, RunRow? LastRun, RunRow? LastLiveRun)
{
    public decimal? EstimateLive(int repeats);   // what the last live run spent a repeat, times the repeats asked
    public bool CanReplay();                      // it has a live run that finished
}
```

When the eval has no live run that finished, or that run had no price, the estimate is none and the ask says the
cost is not known yet, never 0. The API works the rows out and the web shows them (ADR 0042).

### 5. Stopping a run

```
DELETE /v1/admin/evals/runs/{id}     204, the stop was asked
                                     404, no such run
                                     409, the run is not going
```

The route is Microsoft's own for cancelling a long request. The desk that plays the one run holds a cancel signal
for it, joined with the host's shutdown signal into one linked token, which is .NET's tool for listening to both.

```csharp
// RunDesk
public bool TryStop(string id);   // cancels the run going here when it has this id
```

The work that plays the run must tell a person's stop from a shutdown, since they end differently. On a person's
stop it keeps the run as stopped, with the time and one line saying a person stopped it. On a shutdown it leaves
the file as it is, as today, and the run later reads as cut off. So the desk hands the work both signals: the one
it plays under, and the person's own.

`RunStatus` gains `stopped`. A person stopping a run is not the harness failing, so it is not could not finish.

The player already closes its session whatever happens, with no token, so a stopped run leaves no session open,
and the API cancels the agent's turn when its stream is dropped.

### 6. The card starts a run

![Starting a live run from the card, following it on its page, and stopping it](diagrams/F126.3.4-start-follow-and-stop-a-run-communication-a-live-run-started-and-stopped.svg)

The web's client gains a start and a stop. A start answers the run's id, read from the address the API gave, or
the API's own reason when it refused.

```csharp
// EvalsApi
public Task<RunStart> StartAsync(string eval, RunKind kind, int repeats);
public Task StopAsync(string run);

public sealed record RunStart(string? Run, string? Refused);
```

The card's foot holds the two buttons. Replay free is not drawn for an eval with no live run, and one line says
why. Run live opens the ask, a component of its own, `RunAsk`, inside the card: the eval's name in the question,
its conversations, the repeats as two choices, the estimate in a sentence, and two buttons named for what they do,
"Run live, about $0.05" and "Don't run", as Nielsen Norman Group advises. A refusal from the API is shown as a
line on the card, in the API's words.

While any eval's last run is going, a line above the cards says which, that eval's card follows it ("Going since",
"Follow the run"), and the other cards' buttons are off. The API's 409 stays the real guard.

### 7. The run page follows

While the run it shows is going, the page reads the run again every three seconds, and stops when the run has
ended or the page is left. It never asks the person to reload (ADR 0042), so Reload gives its place to Stop for as
long as the run goes. The figures say "So far" where a finished run says "Took", counted from the run's start by
the page's clock, and both costs are what is graded so far.

A stopped run has a box of its own in the place of could not finish: that a person stopped it, that what was
graded is kept, and how many conversations did not run. The evals' card says "Stopped" for it.

A conversation's page shows what judging a turn cost, beside what the turn cost the agent.

### 11. What is reused

No new package and no new project. The start and the address a run is read at are F126.3.1's routes. The stop
uses .NET's `CancellationTokenSource.CreateLinkedTokenSource`. The judge's cost is read from `UsageScope`, and
added with `KnownCost`. Money is written with the web's `UsageFormat.Money`. The page's clock is .NET's
`TimeProvider`, which the web's chat already takes. The buttons are the admin frame's own, and the layout is
Bootstrap's classes.

### 12. The small calls this plan makes

These were too small for a card. Approving the plan approves them, and any of them can be changed with a word.

| The call | Why |
|---|---|
| The stop is `DELETE` on the run's address, 204, 404 or 409 | Microsoft's pattern names it, and the run's file is not deleted by it |
| A stopped run is a status of its own, `stopped` | The mockup and the design review drew it apart, and a person's stop is not the harness failing |
| `JudgeCost` is an init property on a turn, not a part of its constructor | A run's file made before it still reads, with no change to the reader |
| The estimate is the last finished live run's spend a repeat, times the repeats asked, and none when there is no such run | The parent's mockup says "from the last live run's spend", and an unknown cost is never 0 |
| A run in short carries its costs, and an eval's row its last live run | The API works out and the web shows (ADR 0042), and the estimate is asked of the row (ADR 0123) |
| The run's page reads again every three seconds, only while the run goes | Under Nielsen's ten seconds, and a run's file changes about once a conversation |
| The evals' page does not poll | Its cards say a run is going and link to the page that follows it |
| A replay starts with no ask, and plays the live run's own repeats | It is free, and Nielsen Norman Group says not to confirm routine actions |
| Stop has no ask before it | A stopped run can be started again, and the brake should not wait |
| While a run goes the other cards' buttons are off, with one line saying why | One run goes at a time, and the API's 409 is still the guard |
| After a start the browser goes to the run's page | That is where it is followed |
| Replay and Run live are on the card only, not on a run's page | One place to start a run is enough for now |
| The cut-off conversation's spend is on the ledger, not on the run | A run keeps whole conversations only, as picked |

### 13. What this child leaves out

Flips, re-grade and the comparison of two runs are F126.4's. The guide's new evals are F126.5's. A line that says
which turn is being asked now was the option not picked, and can be added later without undoing this. Starting a
run on a schedule, and more than one run at a time, are not planned.

### Step 4: a run can be stopped

The tests come first. In the desk's tests: `TryStop` with the going run's id cancels its work and answers true,

person is kept as `stopped` with its end time, its reason and every conversation graded before, and a run
cancelled by the host's shutdown is left as it was. In the eval routes' tests: `DELETE` on a going run's address
answers 204 and the run then reads as stopped, an unknown id is 404, a run that ended is 409, and the route needs
the admin key. A stopped run is not the run a replay plays back.

Then the code: `RunStatus.Stopped`, the desk's cancel signal and `TryStop`, the work telling the two signals
apart, the handler and its route, and the two messages.
