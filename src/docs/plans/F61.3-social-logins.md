# F61.3 Social logins

> **Plan** (a child of [F61](F61-accounts-and-azure.md), which holds the design, the four diagrams and the namespace
> map). How a person signs in to a site through Google, Microsoft or LinkedIn, each on only when the instance has its
> keys, with linking and unlinking on the profile. Started 2026-11-07 on `feature/F61.3-social-logins`, under the
> parent's approval of 2026-11-07. Deleted when the work is done.

## Done when

A person signs in to Puls with Google, Microsoft or LinkedIn; a provider's button shows only when its keys are set;
the profile links and unlinks a provider, and an account that came in through a provider can set a password.

## Steps

The parent's *F61.3* section, one commit each, test first:

1. The seam: `IExternalProvider`, the `ExternalProvider` enum, the keys in `AccountsOptions`, `/account/providers` live.
2. Google and Microsoft, on Microsoft's own packages.
3. LinkedIn by OpenID Connect, on Microsoft's OpenID Connect package; no third-party package.
4. The routes: challenge, callback (sign in or make the account in the current tenant), link, unlink; a password for
   an account that has none.
5. The buttons and the profile: `ProviderButtons` live, `LinkedLogins` links and unlinks, `SetPassword`.
6. Docs: a guide to registering each app, the feature's TODO for Facebook and X, the write-up.

## Approved during the build

Picks taken unattended (Louis, 2026-11-07: "do all unattended"), each the recommended one of three:

- **The callback is tested with a scripted external sign-in** (step 4): a real provider can't be reached from a
  test. Options: skip the routes' tests; mock Identity's `SignInManager` (a class with twenty methods); **a route the
  test host alone maps, which signs an external identity into Identity's external cookie the way a provider's
  handler would** (picked: the callback runs unchanged, on the same cookie it reads in production).

## Verification

`dotnet test src/tests/hosts/louis-agent.accounts.tests`, the accounts integration tests on the Docker SQL Server,
`src/tests/web/louis-agent.web.tests`. By hand, free: each provider's app registered by Louis with
`http://127.0.0.1:5070/signin-{provider}` as the callback, then sign in, link and unlink. No paid run.
