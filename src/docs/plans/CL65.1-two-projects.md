# CL65.1: Two projects, what a diagram is and what builds it

> **Plan.** The first child of [CL65](CL65-the-diagrams-as-an-engine.md). Everything that builds a diagram moves
> out of `louis-agent.diagrams` into a new project, `louis-agent.diagrams.engine`, which references it. No
> picture changes by a byte.

**Status:** approved 2026-11-14 with its parent (Louis: "approve go unattended"). **Branch:**
`feature/F134.1-the-start-is-a-stage`.

## Context

Louis, 2026-11-14: ".diagrams must be split into a diagrams --> and what builds the diagrams." His picks, in the
parent's plan: two projects, named `louis-agent.diagrams` and `louis-agent.diagrams.engine`, both in `src/web/`.

**What was looked up.**

- *Where the line falls.* Each file was held against one question: does it say what a diagram is, or build one?
  A file that says what a diagram is uses only other such files. The list is under *Design*.
- *Five namespaces are cut in two.* `Cards`, `Tickets`, `Tones`, `Icons` and `Flow.Shapes` each hold records and
  a builder side by side today. A file that used a neighbour without a `using` will need one.
- *The one thread across.* The reader's refusals and the drawings' words are one enum, `DiagramMessage`, filled
  by one internal formatter. Of its 68 members, 25 are refusals and 43 are what a drawing writes.
- *Who references the project.* The framework's web, the docs' tool, the site pack's tests and the diagrams' own
  tests. The web's `GraphView` uses the layout, and its `DrawnCard` the drawings, so the web takes both.
- *The tests.* 78 test files in one project. Five use nothing of the engine. The rest mix a kind's reader and its
  drawing, and share the kind's sample.
- *The rules that will run.* `SolutionLayoutTests` lists the projects of `src/web` by name. The docs' rules ask
  every project doc for its overview and its four pictures. A folder holds six files, and a namespace is its
  folder's path.
- *ADR 0092* already has the rule: a dotted name sits on the thing before the dot. Nothing in an ADR changes.

**What could not be confirmed** before the move: which moved files use a stayed neighbour by its bare name. The
build says, file by file.

## Design

**What stays in `louis-agent.diagrams`: what a diagram is.**

- `Sources/`: the source record, the kinds, the reader, the writer and the JSON options.
- Every kind's `Spec/`, and the cards' records and links, which have no `Spec` folder.
- The two checks the reader runs, `ComponentsCheck` and `CompositeCheck`.
- `TicketCard` and its inputs: they make a source from an agent's call, and draw nothing.
- The names a record is written with: `DiagramTone`, `DiagramIcon`, `NodeShape`.
- The refusals, `DiagramMessage`, with their holes, and the formatter, `DiagramText`.
- `TextWrap`, which the engine uses from there.

**What moves to `louis-agent.diagrams.engine`: what builds one.** Everything else, in the folders it has today,
under the namespace `LouisAgent.Diagrams.Engine`: every layout and what it places, the routing, the adapters
that turn a class chart and a composite into a flow, the keys, `Svg/` whole, the icons' drawings, what a tone
means in a key, and the words a drawing writes.

**The messages are two enums.** `DiagramMessage` keeps the 25 refusals. A new `DrawingMessage` in the engine
holds the 42 words a drawing writes and the one refusal that is the engine's, a kind with no renderer.
`DiagramText` fills either, so it becomes public and takes any message enum.

**One way, held by a test.** `louis-agent.diagrams` references `louis-agent.choices` and nothing else, and no
file in it names the engine's namespace or holds a layout, a renderer, a drawing or the writer.

**One test project.** `louis-agent.diagrams.tests` keeps its name and its folders, and references both
projects. Splitting it would cut most kinds' test files in two and copy their samples, since one test project
may not reference another.

**How the move is made.** A file moves with `git mv`, so its history follows. Its namespace line, and the
`using` lines of whatever names it, are changed by a script that checks each change, and the build proves the
result. That is a script over many files, which ADR 0052 keeps for a pure move: nothing but a namespace's name
changes in any line. Rider's rename, one type at a time, would be some two hundred calls for the same result.

## Steps

One commit each. Unattended: no stop after a step, and every pick is recorded under *Approved during the build*.
After every step the docs' tool must write no picture.

1. **The plan**, its four pictures, and its row in the plans' index. *Test:* none (docs).
2. **The messages in two.** `DrawingMessage` beside `DiagramMessage`, in the one project still, and `DiagramText`
   for any message enum. *Test:* every member of both has its words; every message with holes has its record;
   `DiagramMessage` holds no word a drawing writes.
3. **The engine's project, and the drawings move.** The new project, in the solution. `Svg/` whole, the words,
   the icons' drawings and the tones' meanings move into it. The web, the tool, the site pack's tests and the
   diagrams' tests reference it. *Test:* the solution's layout holds the new project; every test passes as it
   was; no picture changes.
4. **The layouts move, and the direction is held.** Every layout, the routing, the adapters and the keys.
   *Test:* first, seen failing while a layout is still there: `louis-agent.diagrams` references only the
   enum-name parser, names no engine namespace, and holds no layout, renderer, drawing or writer.
5. **The docs.** The diagrams' design doc becomes two, one a project, each with its overview and its pictures.
   The projects' index, the repo map, the guide's links and each project file's doc links follow. *Test:* the
   docs' rules.
6. **Documented and done.** The write-up, the work log, the parent's plan, and this plan deleted.

## Verification

- Each step: `louis-agent.diagrams.tests`, `louis-agent.doc-diagrams.tests`, `louis-agent.web.tests`,
  `louis-agent.pack.site.tests`, and `louis-agent.core.tests` for the rules that read the whole repo.
- Each step: `dotnet run --project src/tools/louis-agent.doc-diagrams` writes no picture, and no golden changes.
- The full suite of unit tests runs before the pull request, with `main` merged in. No paid run.

## Concepts

- Steps 3 and 4: the Common Reuse Principle (Robert Martin, ADR 0092) and a Separated Interface (Fowler): the
  small project is what both sides agree on, and nobody takes what they don't use. Skill 20 (extensibility).
- Every step: a refactor proved by an output that does not change by a byte. Skill 18 (testing and shipping).

## Approved during the build

- **2026-11-14, unattended from step 1,** with its parent. Louis: "approve go unattended."
- **2026-11-14, picked for him before step 1, his to overrule.**
  - *One test project for both.* Reasons above, under *Design*.
  - *The engine's enum is named `DrawingMessage`,* for what it holds: the words a drawing writes.
  - *`DiagramText` becomes public,* so the engine fills its words with the same formatter and not a copy.
  - *`TicketCard` stays with what a diagram is.* It makes a source from an agent's call and draws nothing.
  - *The move is made by `git mv` and a checked script.* Reasons above.
- **2026-11-14, step 2: the messages in two.**
  - *The enum had 68 members, not 69:* 25 refusals, 42 words a drawing writes, and the one refusal that is a
    drawing's, a kind with no renderer. The plan's numbers are corrected in place.
  - *The words' lines moved whole,* from the missing renderer's to the last tone's, into `DrawingMessage`.
    Fourteen files were re-pointed by a script that knows which members moved.
  - *`NoRendererHoles` stays where it is until step 3,* when it moves with the engine's messages.
  - *The holes' test takes a member of either enum.*
- **2026-11-14, steps 3 and 4 are one commit.** The plan had the drawings move first and the layouts after.
  The keys' layouts use the drawings' words and what a tone means, and the drawings use the layouts'
  internal sizes. So with only half moved, the small project would have had to open its internals to the
  engine for one commit, or name the engine. One move has no such in-between.
  - *130 files moved, 75 stayed.* The plan guessed some two hundred. 131 types moved and 75 stayed.
  - *141 files had their `using` lines re-pointed* by the script, in the two projects, the tests, the web
    and the tool. Three lines named a moved namespace in full and were fixed by hand. The whole solution
    builds.
  - *Each of the four users references both projects,* on two lines, so a reader sees both.
  - *The direction's test is in `louis-agent.core.tests`,* beside the one that holds the enum-name parser's
    references, since the rules that read the whole repo live there. It was seen failing before the move.
    It holds four things: the diagrams reference only the parser; the engine references only the diagrams;
    the diagrams hold no layout, renderer, drawing, look, router or writer and never name the engine's
    namespace; and every file of the engine is in the engine's namespace.
  - *The icons' licence moved with their drawings,* and the notices' file and its test point at the new place.
  - *No picture changed:* the docs' tool wrote none, and no golden changed.
- **2026-11-14, step 5: the docs. One design doc, not two.** The plan said the design doc becomes two, one a
  project. It stays one, as it already covered two projects, the library and its tool. Its story follows one
  picture from its file to its SVG, across both projects, and cutting it in two would cut that story. It now
  opens with which project holds what and which way they depend, and its lookup lists both projects' folders,
  written from the disk. The lookup had no row for the component diagram's folders; it has now.
  - *The projects' index, the repo map and both project files say two projects.* The engine's project file
    shows the same design doc and how-to in the IDE.
