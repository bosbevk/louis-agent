# F164.2 The framework Orbi, and the docs layout's rich features

A plan, F164's second child: the framework's site gets its own agent, the framework Orbi, docked beside the page in the
right column, and every rich feature the docs layout named and F164.1 left out: a search in the header, "Ask
Orbi" in the header, "Ask about this page" on the right, and "Ask about this code" on every code listing.

## Context

**What Louis asked** (2026-11-18). "when are we adding rich features?", then "yes nxt but we have too add all rich
features". His picks of that day, each of three options after research:

| # | The choice | His pick |
|---|---|---|
| 1 | What "all rich features" covers | A: one child with everything, the agent with every widget feature louis-agent.dev's guide has, and the docs layout's search, Ask in the header and Ask about this page |
| 2 | What the search searches | A: the site's own places, over the index the guide already uses, with "Ask Orbi" as the last row |
| 3 | How the agent stands on the page | C: a new docked layout, the panel opening in the right column beside the page, the corner on a phone |

And from F164's own picks: "no we give him his own identity", the framework describing itself, labelled AI,
answering from the docs with a doc link; the docs and site packs, not the leads pack, since this site doesn't sell.
Its name (Louis, 2026-11-18: "the agents name is orbi but the framework orbi", "so we have public and framework"):
it is Orbi, as louis-agent.dev's agent is, and there are two of them. The public Orbi is louis-agent.dev's, Louis's
AI agent, selling websites with agents. The framework Orbi is this site's, an identity of its own, speaking for the
framework. Each keeps to its own site.

**What was looked up.** [Mintlify's assistant](https://www.mintlify.com/docs/assistant/use) opens a chat panel on the
right side of the docs, from a button beside the search bar, an "Ask AI" on each code block that adds the snippet as
context, Cmd+I or Ctrl+I, and a `?assistant=` address, with up to three starter questions
([configure](https://www.mintlify.com/docs/assistant/configure)). Microsoft Learn's Ask Learn is an assistant on Learn's
pages ([its FAQ](https://learn.microsoft.com/training/support/ask-learn-assistant-transparency-faq)); how its panel is
laid out could not be confirmed from Microsoft's own pages, so nothing here rests on it.

**What is there.** The framework's widget, `ChatWidget`, has two layouts, `Corner` and `Bar`, one runner under both
(`WidgetLayout`). A question reaches it from anywhere through `GuideDoor`, an Observer the site registers once:
`AskButton` and `GuideButton` put a question through it. louis-agent.dev's guide, `GuideIdentity`, is an identity of
its own on the docs, leads and site packs, run by its host's `SiteCatalog`, open to visitors through `OPEN_IDENTITIES`.
The host keeps an index of the site's own places, `SitePlaces`, rendered from the pages, searched by `PlaceSearch.Find`
for the guide's `FindPlace` tool, with no public route yet. The docs pack reads the docs under `DOCS_ROOT`, which
louis-agent.dev's image fills with the repo's docs. The framework's site's host today runs `AgentCatalog.CoreOnly`, no
identity. `ChatWidget.razor.cs` is near the size limit (ADR 0044), so the docked layout's code is a class of its own.

## Design

### The shape, in plain words

**Its own identity.** `src/site/louis-agent.identity.framework` is the framework Orbi, titled "Orbi · AI" as the
public Orbi is: the framework speaking for itself in the first person, labelled AI (ADR 0113's rule), technical, answering from the docs with a doc link, showing the
place it talks about, and ending each answer with choices, as louis-agent.dev's guide does. Its skills say the site's
pages and the docs' map. It has the docs and site packs.

**Its host runs it.** The framework's host names a catalogue of its own, the identity and the two packs, opens the
door to it, and its image carries the repo's docs as louis-agent.dev's does.

**A third layout, docked.** `WidgetLayout.Docked` draws the widget as a panel in a place the page gives it. The docs
layout gives it the right column: closed, the column shows "On this page"; asked, it shows the panel, and closing it
brings "On this page" back. On a screen too narrow for the right column it is the corner.

**Four ways to ask, one door.** "Ask Orbi" in the header, with Ctrl+I or Cmd+I; "Ask about this page" at
the top of the right column; "Ask about this code" on every code listing, which sends the code with the question; and
the search's last row. Each puts its question through `GuideDoor`, and the docked widget opens and sends it.

**Search over the site's places.** A public route on the host, `GET /v1/site/places?q=`, answers with
`PlaceSearch.Find` over the same `SitePlaces` the guide's `FindPlace` reads, places only, no model. The header's box
lists them by heading; a press opens the place at its own address; the last row asks the agent the same words.

## Steps

Each is one commit, its test written first and seen failing, and a stop after each for Louis's review.

1. **The identity.** `louis-agent.identity.framework`: Orbi's voice, labelled AI, and its skills (the
   site's pages, the docs' map), on the docs and site packs, ending each answer with choices. *Test:* its name, packs
   and prompts' headers; its golden prompt, reviewed.
2. **Its host runs it.** `FrameworkCatalog` in place of `CoreOnly`, the door open to it, the docs in the image and in
   the run profile. *Test:* the catalogue holds the identity and two packs only; the image carries the docs.
3. **A docked layout.** `WidgetLayout.Docked`: the widget as a panel in the place its page gives it, closed until
   asked, with a close that gives the place back; the corner on a narrow screen. *Test:* bUnit, closed draws no panel,
   an ask opens it, close closes it; the corner below the breakpoint.
4. **The docs layout docks it.** `DocsColumns` gives the right column to the panel while it is open, and to "On this
   page" otherwise; the framework's site places its widget docked. *Test:* the column shows one or the other.
5. **Ask in the header and on the right.** "Ask Orbi" in the header, with Ctrl+I or Cmd+I, and "Ask about
   this page" at the top of the right column, each through the door. *Test:* each asks its question; the keys ask.
6. **Ask about this code.** `CodeListing` gains a button that asks about its code, the code sent with the question.
   *Test:* the question carries the listing's name and code; a site with no agent draws no button.
7. **The search's route.** `GET /v1/site/places?q=` on the host, open, places only, from `PlaceSearch.Find` over
   `SitePlaces`, at most eight. *Test:* the route answers a word with its places, none for a word too short.
8. **The search box.** `SiteSearch` in the header: the places as the visitor types, a press opens the place, the last
   row asks the agent the words. *Test:* bUnit, the results drawn, a press goes to the place, the last row asks.
9. **One paid test call.** On :5084, a framework question answered from the docs with a doc link, Ask about this page
   and Ask about this code tried by hand; what it cost reported after. *Check:* by eye at 1280 and 390 px, light and
   dark.
10. **The docs, the write-up, the plan folded.** The identity's doc, the widget's docked layout in the framework web's
    doc, the search route in the API's, the framework site's doc; the write-up; the records.

  *Skill 20, extensibility.*

  only the last row spends a model call. *Skill 8, memory and retrieval.*
