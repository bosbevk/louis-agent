# CL68.3 Minions are lookup agents

A plan, for Louis's approval: CL68's third and last child. A minion becomes a **lookup agent**: a subagent cut down
to one task and one tool, kept inside its agent beside the other subagents, at
`agents/{identity}/subagents/{name}/voice.md` with `level: lookup` in its header, and named by its address. The base
every lookup agent loads first moves to `agents/{identity}/lookup.md`. Eight steps, one commit each, on
`refactor/CL68.3-minions-are-lookup-agents`. The parent plan, [CL68](CL68-agents-and-their-subagents.md), says why;
this one says how.

### How the engine tells a lookup agent from a subagent

Both sit in `agents/{identity}/subagents/{name}/voice.md`. `RoleCatalog.Available(RoleLevel.Subagent)` lists the ones
whose header says `subagent`, and `Available(RoleLevel.Lookup)` the ones whose header says `lookup`, read through the
prompt catalogue, which holds every header once. `FileName(address, Lookup)` is the same path a subagent's is. The
base a lookup agent loads first is its identity's `lookup.md`, found from the address's identity, so the two regular
expressions that read it from a file's name go. The header rule test accepts `subagent` or `lookup` under
`subagents/`, and `lookup` for an agent's `lookup.md`.

## Steps

One commit each, its test written first and seen failing; a review stop after each.

1. **ADR 0021 amended**: a minion is a lookup agent inside its agent, named by its address, on `LOOKUP_LLMS`. A docs
   step, with no test first.
2. **`minion` is `lookup`.** `RoleLevel.Minion` renamed through Rider, its wire name `lookup`, and the two headers say
   `level: lookup`. Test: a header that says `minion` is refused and `lookup` read; it fails first.
3. **One name, the address.** A lookup agent's role is `testprod.lookup`, and only `RoleCatalog` knows its file is
   still `minions/testprod-minion-lookup.md` (CL68.2's order, Louis's pick A there). Test: `AgentAddressesTests`
   resolves `testprod.lookup` to the role `testprod.lookup`; it fails first.
4. **The files move inside their agent.** `git mv` to `agents/testprod/subagents/lookup/voice.md` and
   `agents/testprod/lookup.md`; `RoleCatalog` lists subagents and lookup agents by their headers and finds the base by
   the identity; the base's regular expressions go; the project file stops embedding `minions/`; `PromptFolder.Minions`
   goes and `PromptFileName.Lookup` comes. Test: `RoleCatalogTests` opens `testprod.lookup` from its new path and
   doesn't list it as a subagent; it fails first.
5. **`LookupAsk` and `LOOKUP_LLMS`.** `MinionAsk` and `MinionLlms` renamed through Rider, the setting read as
   `LOOKUP_LLMS`, its messages and `.env.example`. Test: `AgentOptions` reads `LOOKUP_LLMS`, and `MINION_LLMS` sets
   nothing; it fails first.
6. **The API and the chat say lookup agent.** The roles reply's `lookups`, the chat's labels. Test: the reply's
   fields and the work panel's label; they fail first.
7. **The model's guide says lookup agent.** The `agents` guide's section and the tool texts; the golden files
   regenerated and their diff read, the word only. No test first: what the model reads is pinned by the goldens.
8. **The docs, and CL68 closed.** *Build an identity*, the projects' docs, SETUP, the framework pages (a test holds the
   new word, as for subagent), the glossary and the pictures; the write-up's section in
   `10-multi-agent-orchestration.md`; this plan and CL68's folded, and CL68's row moved to the work log
   (`/finish-a-feature`).

## Concepts

- **Cheap workers** (steps 2 to 5): a lookup agent is a subagent cut down to one task and one tool, so a small model
  can do it. That's the cost side of delegation. GOAL.md skills 1, *Model selection*, and 10, *Multi-agent
  orchestration*.
- **The header decides the kind** (step 4): two kinds of helper in one folder, told apart by what each file says it
  is, not by where it sits. Skill 3, *Prompt design*.
