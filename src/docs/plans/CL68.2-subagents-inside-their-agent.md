# CL68.2 Subagents inside their agent

A plan, for Louis's approval: CL68's second child. A specialist becomes a **subagent**, kept inside the agent it
belongs to, at `agents/{identity}/subagents/{name}/voice.md`; its one name everywhere is its address,
`{identity}.{name}`; and a prompt's level comes from its header, not its folder. Seven steps, one commit each, on
`refactor/CL68.2-subagents-inside-their-agent`. The parent plan, [CL68](CL68-agents-and-their-subagents.md), says
why; this one says how.

## Design

### What changes

| Today | After |
|---|---|
| `specialists/triage-sorter.md`, `level: specialist` | `agents/triage/subagents/sorter/voice.md`, `level: subagent` |
| A role named `triage-sorter`; an address `triage.sorter` turned into it | One name, `triage.sorter`, in the address, the session's `role`, `ROLES_ENABLED`, the evals |
| `RoleLevel.Specialist`, found by its folder (`RoleCatalog.FolderOf`) | `RoleLevel.Subagent`, found under its agent, its level read from its header |
| `TriageRole` with `[WireName("triage-sorter")]` | The triage team names its subagents by their addresses alone |

### How the engine finds a subagent

`RoleCatalog.FileName("triage.sorter", RoleLevel.Subagent)` is `agents/triage/subagents/sorter/voice.md`: the
identity, then the subagent, as the address reads. `AgentAddresses.Resolve` stops building a dashed name and asks for
the address itself. `RoleCatalog.Available(RoleLevel.Subagent)` lists every `agents/*/subagents/*/voice.md` by its
address. The name pattern takes one dot between an identity and its subagent, as it takes one slash between a
product and its mode.

### The level, from the header

A prompt's header already carries `metadata.level` (ADR 0063), and the catalogue already reads it for every prompt.
So the engine trusts it: a subagent's `voice.md` says `subagent`, an agent's `agent`. A layout test reads every
prompt and refuses a header level that doesn't match where the file sits, so a subagent can't open as an agent.

## Steps

One commit each, its test written first and seen failing; a review stop after each.

1. **ADR 0133**, as approved, with ADR 0017 marked superseded and its row in the index, the solution and the design
   rules. A docs step, with no test first.
2. **`specialist` is `subagent`.** `RoleLevel.Specialist` renamed through Rider, its wire name `subagent`, and the
   four headers say `level: subagent`. Test: a header that says `specialist` is refused and `subagent` read, in
   `PromptHeadersTests`; it fails first.
3. **One name, the address.** `RoleCatalog`'s name pattern takes `{identity}.{name}`, and `AgentAddresses.Resolve`
   asks for the address as the role, with no dashed name built. Test: `AgentAddressesTests` resolves `testprod.specialist`
   to the role `testprod.specialist`; it fails first.
4. **The files move inside their agent.** The four files `git mv` to `agents/{identity}/subagents/{name}/voice.md`,
   `RoleCatalog.FileName` and `Available` find them there, the project files stop embedding `specialists/`, and the
   tests' and settings' names become the addresses. Test: `RoleCatalogTests` opens `testprod.specialist` from its new
   path; it fails first.
5. **The level from the header.** The layout test refuses a prompt whose header level isn't its place's: `subagent`
   under `subagents/`, `agent` for an agent's own voice. Test: it fails first on a test prompt placed wrong.
6. **The triage team's one name.** `TriageRole` and its dashed names go; the team's tests, its evals' `eval.json`
   (`"role": "triage.sorter"`) and its catalogue use the addresses. Test: `TriageRolesTests` and `TriageEvalsTests`
   read the addresses; they fail first.
7. **The docs, and closed.** *Build an identity*, the projects' docs, the API's doc on `role`, Setup on
   `ROLES_ENABLED`, the architecture and the glossary, their pictures redrawn, the write-up's section in
   `03-prompt-design.md` and `10-multi-agent-orchestration.md`, and this plan folded (`/finish-a-feature`).

## Concepts

- **Subagents** (steps 2 to 4): a subagent runs on the same loop as the agent you talk to, with less context: its own
  instructions, its own tools, a fresh conversation. That's what sets it apart, not a different engine, the same idea
  as Claude Code's subagents. GOAL.md skill 10, *Multi-agent orchestration*.
- **One name per thing** (step 3): the address a caller writes is the path the engine reads and the name the logs
  show. Skill 3, *Prompt design*.
- **Package by feature** (steps 4, 5): everything one agent has, in its folder, with a test keeping what the folder
  per level used to. Skill 18, *Testing and shipping*.
