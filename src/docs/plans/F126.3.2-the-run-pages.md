# F126.3.2 The run pages

A plan: how a run of an eval is read in a site's admin. It is the second child of F126.3, *runs and the run page*,
in [F126 Evals, redesigned](F126-evals-redesigned.md), which says what was decided and why. This file says what this
child builds, then gives its eleven steps. It builds three pages that read, and nothing that starts a run: that is
F126.3.4's.

![Five parts: an area a site opts into, a client that reads the eval routes, the list of evals, a run with its conversations failed first, and a conversation turn by turn](diagrams/F126.3.2-the-run-pages-overview.svg)

## Context

**What Louis asked.** "merge is in plan next" (2026-11-23), after F126.3.1 merged as pull request 538. Before that,
of the screens: "there is no eval pages today... we think anew" and "each site will have it's own evals in their
admin" (both 2026-11-22).

**Why this child is cut in two.** Counted honestly, the pages are about fifteen steps. They fall into two halves that
don't need each other. One half reads: the list of evals, a run, a conversation. The other starts: the ask before a
live run with its estimate, the page that follows a run while it plays, Replay and Stop. Louis picked the split, so
this child reads and F126.3.4 starts. F126.3.3 stays the name of the page a conversation names.

**What the code has, on `main` at `8590819c`.** The API side is whole. `LouisAgent.Api.Evals` maps four routes behind
the admin key: the list of evals, the start of a run, a run by its id, and an eval's runs, newest first. Every answer
is the run's own JSON, in the records of `LouisAgent.Evals.Contracts`, a project that references nothing so a browser
project can take it. A run already answers whether it passed: `Passed` is a property on the run, the conversation and
the repeat.

The admin's frame is whole too. A page in it names the frame as its layout, reads through the API client every site
has (`AgentApi`), and shows the key box (`AdminGate`) when the key is refused. `Pages/Admin/Packs.razor` in
`LouisAgent.Web` is the model. A part a site opts into is a project of its own with one word on the areas builder:
the accounts, the docs and the places are each built that way. An area brings its link for the admin's sidebar and
its card for the admin's home, as the site's own Resume area does.

Three things are missing, and they are this child. No page reads the eval routes. The options a run's JSON is read
with (`RunJson`) sit in `LouisAgent.Evals`, which stands on the engine, so a browser can't reach them. And a run
doesn't answer the other questions a page asks, such as how many facts were met or why a conversation failed.

**What the drawings are.** The mockups in [F126-mockups/](F126-mockups/) show the old console look and things since
picked away, so the three screens and two states were drawn again before this plan, inside the running admin of
louis-agent.dev, from its own page head, cards, sidebar link and buttons, with theme names for every colour and
Bootstrap's grid. Louis picked "Yes, as drawn". They are in [F126.3.2-screens/](F126.3.2-screens/) and each step
that builds a page names its picture. Where a drawing and this plan differ, the plan wins, and the two places they
do are said in section 8.

## Design

### 1. Three pages, in plain words

Someone with the admin key opens Evals in the sidebar and sees one card per eval file the host has. A card says the
eval's name, the agent it proves, how many conversations it holds, and how its last run went. From a card they open
the last run.

A run's page gives the number first: how many conversations passed, of how many. Then what it ran with, and then
the conversations, the failed ones first, each saying in one line which repeat failed and on what. At the foot are
this eval's other runs.

A conversation's page shows one repeat at a time. Each turn is what was asked, the tool calls folded away, the
answer, and its marks: a fact with a tick or a cross, a criterion with the judge's one line of why. A switch picks
the repeat, and two links walk to the previous conversation and the next failed one.

Reading is the whole of it. Anthropic's advice on evals is to read the transcripts, and these pages are where that
happens.

### 2. Where the pages live

![The area and its parts: the builder's word, the client, the addresses, three pages and the components they share, and the run's records with the methods the pages ask](diagrams/F126.3.2-the-run-pages-interface-design.svg)

The pages are a new project, `LouisAgent.Web.Evals`, a Razor class library on `LouisAgent.Web` and
`LouisAgent.Evals.Contracts`. A site takes it with one word among its areas:

```csharp
public static class EvalsArea
{
    public static SiteAreasBuilder Evals(this SiteAreasBuilder areas);
}
```

That word registers the client, hands the router the library's pages, and gives the admin its Evals link in the
sidebar and its card on the home. A site that names no evals ships none of it, which matches how the API side is
taken (`AddLouisAgentEvals`). The pattern is the repo's own area, the one the accounts and the docs use
(ADR 0084, ADR 0120).

`RunJson`, the one options object a run is written and read with, moves from `LouisAgent.Evals` into the contracts.
It uses nothing but .NET's own JSON, so the contracts still reference no project of ours, and the page reads a run
with the very options the store wrote it with.

The project is not a package yet, as the contracts aren't (ADR 0130).

### 3. A run answers what a page asks

Louis's pick is that the records answer, as `Passed` already does. A method is not written into the run's file,
where a property is, so the file and the API's answers stay as they are.

```csharp
public sealed record Tally(int Met, int Of);

// On RepeatRun
public Tally CountFacts();
public Tally CountCriteria();
public decimal? SumCost();          // the turns' known costs; null when none has a price
public TimeSpan SumTime();
public Miss? FindFirstMiss();       // the first mark not met: which turn, a fact or a criterion, its words

// On ConversationRun
public int CountPassedRepeats();
public RepeatRun? FindFirstFailedRepeat();
public string? FindFirstAsk();      // its first repeat's first turn's ask

// On EvalRun
public Tally CountFacts();
public Tally CountCriteria();
public decimal? SumCost();
public TimeSpan? MeasureTime();     // from its start to its end; none while it runs
public IReadOnlyList<ConversationRun> OrderFailedFirst();
public ConversationRun? FindNextFailed(string after);
public ConversationRun? FindPrevious(string before);
```

`Miss` is a small record: the turn's number, whether the mark was a fact or a criterion, and the mark. Every one of
these is a method and none a property, because a get-only property would be written into the run's file.

A cost nobody could price stays null and is shown as unknown, never 0 (ADR 0007). The sums follow the rule the
ledger's own total follows: the known parts added, and null when no part has a price.

The names follow ADR 0126, a method a verb. If a name here reads badly once it is used, that is a naming finding for
Louis, not a quiet rename.

### 4. Reading the routes, and the addresses

```csharp
public sealed class EvalsApi(AgentApi api)
{
    public Task<EvalsReply> ListAsync();
    public Task<EvalRun?> FindRunAsync(string id);
    public Task<IReadOnlyList<RunRow>> ListRunsAsync(string eval);
}
```

`EvalsApi` is one small class over the API client every site has. It reads with `RunJson.Options`, and a run the
host doesn't have is none, not an error. A refused key and a host that can't be reached come through as the API
client's own exceptions, which every admin page already turns into the key box or a plain line.

`EvalAddress` holds every address in one place, the pages' and the routes', so no page builds one by hand:

| Page | Address |
|---|---|
| The evals | `/admin/evals` |
| A run | `/admin/evals/{eval}/runs/{run}` |
| A conversation, at a repeat | `/admin/evals/{eval}/runs/{run}/{conversation}/{repeat}` |

The repeat is part of the address and never a `#`, so a repeat can be linked and the browser's Back works
(ADR 0107). A conversation's address with no repeat opens the first repeat that failed, or the first.

### 5. The pages and their parts

![One conversation opened: the page asks the client for the run, the client reads the route with the run's own options, and the page asks the records what to show](diagrams/F126.3.2-the-run-pages-communication-opening-a-conversation.svg)

Each page is a `.razor` of markup and a code file beside it (ADR 0034). A page loads the admin key, reads through
`EvalsApi`, and holds what it last read. It shows what it fetched, and Reload fetches again (ADR 0042). There is no
timer and nothing polls: following a run as it plays is F126.3.4's.

The shapes more than one page draws are components of the library, each drawn once:

| Component | What it draws | Used on |
|---|---|---|
| `MarkDot` | The tick or the cross, with its words for a screen reader | every page |
| `RunFigures` | A row of named figures, such as Took and Facts met | a run, a conversation |
| `ConversationRow` | A conversation in a run: its id, its first ask, why it failed, "2 of 3 repeats" | a run |
| `RunRows` | An eval's runs, newest first, this run marked | a run |
| `RepeatSwitch` | One link per repeat, the open one marked | a conversation |
| `TurnCard` | A turn: the ask, the tool calls in a fold, the answer, the marks | a conversation |
| `MarkLine` | A fact in code type, or a criterion with the judge's line | a turn |

The layout is Bootstrap's classes in the markup. The library's own Sass writes only what Bootstrap and the frame
don't give, and reads theme names for every colour, so glass and flat, dark and light all work with no rule per
theme (ADR 0085, ADR 0124). Numbers are in the theme's monospace face, and every link and button is at least 24
pixels high with the frame's focus ring, as the design review asked.

A date is shown in the browser's own time, the way the overview shows when a talk was. The run's file keeps UTC
(ADR 0046).

### 6. The states

A page says plainly what it could not show. These are all of them:

| Where | The state | What the page shows |
|---|---|---|
| Any page | The key is refused | The frame's key box, as on every admin page |
| Any page | Still loading | One quiet line |
| The evals | The host has no eval file | One card: where a file goes, and the guide on writing one |
| An eval's card | Never run | "Not run yet." |
| An eval's card, a run | The run could not finish | The reason first, in the run's own words, then what was graded |
| A run | Still running | What is graded so far, and Reload |
| A run, a conversation | The host has no such run or conversation | One line that names what was asked for |

A run that could not finish says how many conversations did not run, not which: a run keeps the conversations it
graded, and the eval's list gives only a count. A conversation that stopped part way shows the repeats it has.
