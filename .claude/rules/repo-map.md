# Where things are in the repo

Loaded in every session, with `src/docs/CLAUDE.md`.

Where things are. What's inside each project is in its design doc in [projects/](../../src/docs/projects/README.md); core's folders
in [Project layout](../../src/engine/LouisAgent.Core/CLAUDE.md#project-layout).

```
src/engine/              # LouisAgent.Core (the loop, delegation, web access and its guards, skills, providers, usage, bootstrap), LouisAgent.Choices (the one enum-name parser), .SessionStream, .Composition (the contracts everything agrees on); LouisAgent.Core.Web (the browser, search, robots, rendering, the recorders), .Core.Telemetry (the tracer, the collector's sink), .Core.Anthropic, .Core.Ollama and .Core.OpenAi (one model SDK each), each on core behind a seam, a host opts in (CL33, CL57)
src/hosts/               # LouisAgent.Cli, .Acp (Rider, with its tool discovery), .Api (sessions + SSE; serves a web app), .Api.Evals (the eval studio, a program opts in), .Api.Contracts, .Accounts, .Accounts.Contracts, .Mcp (the tools, no model)
src/web/                 # LouisAgent.Web: the framework's web, what every site shares; LouisAgent.Web.Accounts: the account pages, LouisAgent.Web.Evals: the eval studio's pages, LouisAgent.Web.Places: every place's own address, its catch-all, LouisAgent.Web.Docs: a doc linked by its path and the pages' reading order, LouisAgent.Web.Framework: the framework's own pages, a site opts into each; LouisAgent.Web.Themes: the themes, glass and flat, a folder each, values a site names among its areas; LouisAgent.Diagrams: what a diagram drawn from data is, its kinds, records and reader; LouisAgent.Diagrams.Engine: what builds one, the layouts and drawings, on it; plain C# the web and the docs' tool share
src/evals/               # The eval harness, its protocol, the checks contract, the runner and the template folder
src/site/                # The framework's websites (F124, ADR 0111): LouisAgent.Site (louis-agent.dev, the visitor area that sells), LouisAgent.Identities.Guide (the guide in its corner), LouisAgent.Identities.Framework (the framework Orbi, docked beside the framework's pages), LouisAgent.Identities.Showroom (three made-up businesses' agents), LouisAgent.SiteApi (its host), LouisAgent.SiteFramework and LouisAgent.SiteFrameworkApi (the framework's own site and its host, F164.1), config/, docker/, deploy/; the one place in src/ that uses packs and an identity, and nothing else in src/ references it
packs/                   # What an agent can do, one area (CL32): tools/ (the packs, tools only: files, git, dotnet, shell, web, paymo, devops, calculator, where-to-buy, shop-prices, recipes, docs, leads, site, triage), evals/ (what proves a pack, apart so someone can take the tools without it; only the runner references these), tests/ and web/ (a pack's own tests and its own web views, apart from its tools, ADR 0086), docs/
demos/puls/              # A demo, as someone's own project would be: identity/ (who it is), evals/ (an eval is a folder of files), web/ (its app), hosts/ (host-packs picks its packs), config/, docker/, skills/ (what the agent writes), deploy/ (Azure), tests/, docs/, and git-ignored data/ and logs/
demos/louis-agent/       # Our own demo: identity/ (the coding agent, the triage team), web/ (code review: the coding agent's chat and admin), hosts/ (the orchestrator POC, and the programs that start the framework's hosts), config/, docker/, skills/, tests/, docs/, and git-ignored data/ and logs/
demos/starter/           # The smallest site (web/), its API program (hosts/) and what `dotnet new louis-site` makes ([Spawn a site](../../src/docs/guides/spawn-a-site.md))
src/tools/               # LouisAgent.UsageProbe: a provider's raw usage; prices and totals a ledger. LouisAgent.FilmExport: the site's films to WebP. LouisAgent.DocDiagrams: the docs' diagrams from their JSON. rename-projects: the commands F167 ran once to name every project for its namespace, kept as the record
src/tests/               # Only the framework's tests, grouped like src/ ([tests](../../src/docs/projects/tests.md)); a demo holds its own tests/ and packs/tests/ the packs'; the ones that leave their process are *.integration-tests
src/docs/                # The framework's docs: this guide, adr/, guides/, projects/, plans/, fixes/, learning/, architecture/
.claude/                 # What Claude Code reads: rules/ (the how of a kind of file, loaded by path; the design rules and this map, always), skills/ (a procedure per job), README.md (how they are laid out)
```
