# Fixes: what broke, why, and how it was fixed

Features add something; fixes repair something that didn't work. Each fix gets a short doc here: the symptom as it was
seen, the cause once found, the fix, how it is tested and how it was confirmed. When a fix is done its doc is folded
(*Finishing a fix*, step 5): its row below keeps the symptom and the cause, so the next person who sees the same error
finds why, and its lesson moves to the write-ups ([Lessons from the fixes](../learning/fixes-lessons.md) holds
those folded on 2026-10-29; every doc as it was is at the tag `pre-cl24`).

## Conventions

A fix's id is `FXn`, numbered in the order the problems were found, and its doc is `FXnn-short-name.md`. Each doc
has the same parts. *Symptom* is what was seen, with the exact error. *Cause* is proved, not guessed, and says how it
was found. *Fix* is what changed and why it was done this way. Then come *Tests*, *Confirmed* (the real run that shows
it works) and *Lesson* (the idea behind it, and its skill in the goal's map).

A fix's status is *open* or *done*, the same here and at the top of its doc. A fix that takes more than one step gets
its approved plan in [plans/](../plans/README.md) (`FXnn-name.md`), committed before its first step. An open fix also
has one line in the [TODO](../../../TODO.md), in its phase's section, linking here, and a fix that removes a known
limitation names it.

## Finishing a fix

The list a fix finishes by is in the skill that loads when a fix starts:
[fix-a-bug](../../../.claude/skills/fix-a-bug/SKILL.md#finishing-a-fix). Its steps keep their numbers, so
*Finishing a fix, step 5* is the fold.
