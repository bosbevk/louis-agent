# F166.3 Puls in its own repository

A plan: Puls and its three packs move to `github.com/bosbevk/puls`, under names of their own, in the usual .NET
layout, reaching the framework only through its published packages. It is the third child of
[F166 Puls in its own repository](F166-puls-in-its-own-repo.md). Removing Puls from louis-agent is the fourth, F166.4.

## Context

The framework is published as 31 packages at `0.1.0` (F166.2, ADR 0130). Louis's picks for this child, 2026-11-21,
each of three options after research:

| # | The choice | His pick |
|---|---|---|
| 1 | Does Puls keep its git history | A: a fresh start, the first commit naming the louis-agent commit and a tag it came from |
| 2 | Puls's licence | A: PolyForm Noncommercial 1.0.0, the framework's, replacing the repository's Apache 2.0 file |
| 3 | The layout | B: the usual .NET shape, `src/` and `tests/` at the root, every project under one of them |
| 4 | The names | A: Puls's own, `Puls.*`, code namespaces included, a project's name its namespace as ADR 0129 has it |
| 5 | The test helpers find only louis-agent | A: `TestPaths` finds the nearest folder above holding any `*.sln` or `*.slnx`, released as `LouisAgent.Testing 0.2.0` |

**What was looked up.** Puls is 582 tracked files under `demos/puls` and 328 for its three packs (`recipes`,
`shop-prices`, `where-to-buy`, with two checks projects, a web view and eight test projects): 26 projects and 388 C#
files. Its projects reach 31 framework projects, all published. No framework project grants its internals to a Puls
project. `TestPaths.RepoRoot` walks up to `louis-agent-solution.sln`, and Puls's manual tests do the same walk of
their own; only louis-agent's two samples carry another solution file, inside the samples. The coming-soon page is
published by `deploy-coming-soon.yml` with the repository secret `PULS_COMING_SOON_TOKEN`. The `puls` repository is
public and holds only an Apache 2.0 licence.

**Not known yet, said plainly.** Whether every Puls test passes from packages alone: some may reach a framework file
by a path into louis-agent (a prompt, a fixture). Step 4's run in the new repository shows it, and each one found is
fixed there or put to Louis.

**Put to Louis with this plan, each with the one recommended.** The move is done the way F167's rename was: git and
shell commands run once, kept as the record, with no tests (Louis's pick for F167), over Rider renames by hand or a
tool. The names, read off the projects:

| Today | In `puls` |
|---|---|
| `LouisAgent.Identities.Puls`, `.Evals`, `.Judges` | `src/Puls.Identity`, `src/Puls.Evals`, `src/Puls.Judges` |
| `LouisAgent.Puls`, `LouisAgent.PulsApi`, `LouisAgent.PulsEvalRunner`, `LouisAgent.HostPacks` | `src/Puls.Web`, `src/Puls.Api`, `src/Puls.EvalRunner`, `src/Puls.HostPacks` |
| `LouisAgent.Packs.Recipes`, `.ShopPrices`, `.WhereToBuy`, with `.Checks` and `.Web` | `src/Puls.Packs.Recipes`, `src/Puls.Packs.ShopPrices`, `src/Puls.Packs.WhereToBuy`, `…Checks`, `…Web` |
| each `….Tests` and `….IntegrationTests` | `tests/` under the new name and `.Tests` or `.IntegrationTests`; `LouisAgent.Puls.Tests` is `Puls.Web.Tests` |

Docs, config, docker, deploy and skills sit at the root beside `src/` and `tests/`, as `docs/`, `config/`, `docker/`,
`deploy/` and `skills/`; the solution is `Puls.sln`.

## Design

![Puls in its own repository, its projects under src and tests, reaching the framework's packages on GitHub Packages](diagrams/F166.3-puls-in-its-own-repo-architecture.svg)

### 1. The one change to the framework

`TestPaths.RepoRoot` takes the nearest folder above the tests that holds a solution file, whatever it is called, so a
product's tests find their own repository. It ships as `LouisAgent.Testing 0.2.0`, tagged on `main` after it merges:
the release flow's first real use beyond the first release.

![TestPaths finds the nearest solution, used by the framework's tests and Puls's](diagrams/F166.3-puls-in-its-own-repo-interface-design.svg)

### 2. The move

![The test helpers released first, then the commands copy Puls into its new layout, and Puls's CI proves it](diagrams/F166.3-puls-in-its-own-repo-communication-the-move.svg)

The commands read Puls's files at a commit of louis-agent tagged `puls-moved-out`, write them into a working copy of
`puls` in the new layout, rename each project, folder, namespace and reference by the table above (whole names,
longest first, as F167's commands did), and turn every reference to a framework project into a `PackageReference` at
its published version. A `nuget.config` names GitHub Packages beside nuget.org. A dry run prints the moves and the
counts first.

![One run holds the map of 26 renames and turns framework references into package references](diagrams/F166.3-puls-in-its-own-repo-objects-in-memory.svg)

### 3. What is reused

F167's commands, their whole-name rule and their reports. F166.2's `consume-packages.yml` for how a workflow restores
from GitHub Packages with its own token. louis-agent's `ci.yml` and `deploy-coming-soon.yml`, adapted. No new package.

## Steps

Each step is one commit, in louis-agent or in `puls` as it says, with its test where it has code. Stop after each for
Louis's review; a push or a tag waits for his word.

1. **The plan is kept** (louis-agent). This plan, its pictures, and its records.
2. **`TestPaths` finds any solution** (louis-agent). Test first: a folder holding `Any.sln` is the root from a folder
   below it. Then merged, and `LouisAgent.Testing-0.2.0` tagged on `main` on Louis's word.
3. **The move's commands, kept, and their dry run** (`puls`, in `tools/moved-from-louis-agent/`). The names, the moves,
   the package references, shown before anything runs.
4. **The move** (`puls`). The first commit, naming louis-agent's commit and the tag `puls-moved-out` (pushed on Louis's
   word). Puls builds from the packages and its tests pass on this PC; what doesn't is fixed or put to Louis.
5. **Puls's CI** (`puls`). Build and unit tests on every pull request, restoring from GitHub Packages with the run's
   own token; the integration tests as louis-agent runs them.
6. **The coming-soon page** (`puls`). Its folder and its workflow move; Louis sets `PULS_COMING_SOON_TOKEN` in `puls`.
   louis-agent's copy stays until F166.4.
7. **The licence and the front door** (`puls`). PolyForm Noncommercial in `LICENSE`, a README that says what Puls is,
   how it builds on the framework's packages, and where its history before the move lives.
8. **The close** (louis-agent). The write-up, the records, this plan folded and deleted.

## Verification

Step 2's test, and louis-agent's suite with `LouisAgent.Testing` changed. In `puls`: the dry run read by Louis, then
the build and the tests on this PC and on its own CI, restoring the framework from GitHub Packages alone. The
coming-soon page answers at mypuls.co.za after its workflow runs there. No paid run.

## Concepts, and where they sit in GOAL.md

- **A product on a framework** (steps 3 to 7): Puls as the framework's first outside user, names and layout of its
  own, the framework only as packages. *Skill 20, extensibility.*
- **A framework change found by its first user** (step 2): what only shows once a product lives elsewhere, fixed and
  released like any version. *Skill 18, testing and shipping.*

## Approved during the build

**2026-11-21, finding 6, Louis's "a".** Puls's first build outside louis-agent stopped at its styles. Its Sass forwards
the framework's own partials, such as `web/settings/colours`, and found them through `sasscompiler.json` paths into
louis-agent's `src/web`, while the web packages carried only compiled CSS. So before step 4 can finish, a step 3b in
louis-agent makes a package that holds Sass carry it under `sass/`, together with a shared `buildTransitive` file that
copies it into the site's `obj/framework-sass/` before the Sass compiler runs. A site then names that one folder in
its `IncludePaths`. `LouisAgent.Web` and `LouisAgent.Web.Evals` (the two with Sass) are released at `0.2.0`. That was
picked over sites dropping the framework's Sass for its CSS variables (B) and copying the partials into Puls (C).
Puls's eval runner becomes `Puls.Evals.Runner`, since `Puls.EvalRunner` clashed with the framework's `EvalRunner`
type.

**2026-11-21, finding 7, Louis's "a".** The shared build file lives at `src/web/FrameworkSass.targets`, beside the web
projects whose packages carry it, rather than in a new top-level `build/` folder (which would have needed a fifth
solution group) or at the root.
