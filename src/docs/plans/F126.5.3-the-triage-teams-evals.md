**What was looked up.** The demo's API program (`demos/louis-agent/hosts/LouisAgent.CodingApi/Program.cs`) takes the
API and the accounts, and maps no eval routes; its compose service mounts the repository at `/workspace`, keeps the
triage team's runs and its people's cases under `demos/louis-agent/data/triage/` (git-ignored), and sets no
`SITE_DATA_DIRECTORY` or `REPLAY_DIRECTORY`; `AGENT_PEERS` is empty unless `config/.env` sets it. The code-review
app's areas (`CodeReviewAreas`) name an admin with its overview and packs' screens. An eval file names one agent, an
identity or one of its roles (`EvalFile.Agent`). The triage manager's voice names four paths: an exception the
runbook expects is ignored, one the runbook gives a person (payments, money, data, no runbook, unsure) is raised,
one worth investigating goes to the investigator, and on the investigation it decides a hand-off, a person or an
auto-fix. The triage pack's tools write only local files: a run's steps and, for `RaiseToPerson`, a case for a
person under the people folder; in an eval's trial an unknown run id starts a run. The roles are `triage.sorter`,
`triage.investigator` and `triage.reviewer`; the coder is a peer, not one of them. The sample order service,
`demos/louis-agent/samples/order-service`, has ten seeded bugs and runbooks in
[orchestrator-runbooks](../../../demos/louis-agent/docs/projects/orchestrator-runbooks.md): `refund 1002` is expected,
`refund 1005` is a payments bug a person must see, `order-total 1003` is an auto-fixable `KeyNotFoundException`. The
deleted triage evals (before F126.1) briefed a role with the run id, the repository, the error and the method's
runbook, the shape this eval's asks keep. `routed-to` is met when the turn asked the address with `AskAgent`, and
`continued` when this turn and an earlier one both did (`Facts.cs`). Since FX235 a replay plays back what each tool
answered, so the investigator's reads of the sample are replayed, not run.

## Design

The demo's API host takes the evals as the two sites' hosts do, and the code-review app's admin shows them. The
manager's eval sits beside its voice, embedded with the identity's prompts. Each conversation is a case the way the
feed would hand it: the run id, the department's repository in the workspace, the error as its JSON line, and the
method's runbook. The run ends at the manager's decision: no coder is a peer of the eval's host, so an auto-fix is
decided and briefed, never carried out.

**The conversations**, one per path the manager's voice names, on the sample order service: `refund 1002`, an
exception the runbook expects, is ignored (`used DecideCase`, `not-used RaiseToPerson`); `refund 1005`, a payments
bug, goes to a person (`used RaiseToPerson`); `order-total 1003` is investigated, then decided auto-fix
(`routed-to triage.investigator`, `used DecideCase`); an error that is another department's is handed off; a method
with no runbook goes to a person; and a two-turn case where the manager asks the investigator again after a
follow-up (`continued triage.investigator`). The judge marks the reasons and the briefs. The exact cases are written
in step 4 from the runbooks and the samples as they stand.

## Steps

1. **This plan**, with its records.
2. **The demo host takes the evals, and its data.** Its program adds `AddLouisAgentEvals` and `MapLouisAgentEvals`
   behind the admin key; its compose service and run profile get `SITE_DATA_DIRECTORY` and `REPLAY_DIRECTORY` under
   `demos/louis-agent/data/`. Tested first: the program takes them, the service names the folders.
3. **The admin page.** `CodeReviewAreas` names `.Evals()`, so the code-review admin shows the runs. Tested first in
   the app's areas test; looked at on `:5082`.
4. **The manager's eval.** `triage.eval.json`, about six conversations as above, embedded with the identity. Tested
   first: a conversation per path, the routing facts present, every tool a fact names the manager's own, and no
   conversation that reaches the coder.
5. **The baseline.** A live run of three repeats on Louis's go (about $0.20 to $0.40; the team asks its roles and
   reads the sample), the judge's reasons read, each first repeat into `demos/louis-agent/recordings/evals/triage/`,
   scanned before staging; `TriageEvalReplayTests` replays every conversation, written first and seen failing with
   nothing recorded.
6. **The docs.** The demo host's, the code-review app's and the triage team's design docs, and the run-an-eval guide.
7. **F126 closes.** The write-up in `12-evaluation.md`, the records, and this plan, F126.5's and F126's folded and
   deleted, what lasts already in ADR 0134 and the design docs.
